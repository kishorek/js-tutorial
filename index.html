The only pacing rule

Finish the lesson's exercise before reading the next lesson. This page deliberately stops at Lesson 1.1. You will not get Lesson 1.2 until you show me your work.

How you'll learn

Understanding beats memorizing.

I will not hand you a wall of syntax and hope it sticks. Each lesson introduces one idea, shows it visually, has you predict the result, then asks you to build something small with it.

  1. Predict before you run. A wrong prediction is more useful than a lucky guess. It shows exactly where your mental model breaks.
  2. Type, don't paste. Typing forces you to notice brackets, quotes, and closing tags. Copying hides the mistakes that teach you.
  3. Break it on purpose. Delete a closing tag. Change one letter. See what the browser does, then repair it. Controlled failure builds confidence.
  4. Explain it simply. If you cannot explain a concept to a friend in one minute, you do not own it yet. We will revisit it.

1.1 Three languages, one page

Think about a house. The frame, walls, and room labels decide what exists and where it goes. The paint, lighting, and furniture decide how it looks. The wiring and switches decide what responds when you flip something.

A webpage is the same three layers:

LanguageIts jobThink of it asWithout it
HTMLStructure and meaning: what each piece of content is.The frame, walls, and room labels.A wall of unstyled text with no hierarchy.
CSSPresentation: color, type, spacing, layout, animation.The paint, lighting, and furniture.Readable, but it looks like a document from 1995.
JavaScriptBehavior: respond to clicks, validate input, fetch data, update the page.The wiring and switches.Readable and attractive, but static.

We start with HTML on purpose. A beautiful house on a rotten frame is still a rotten house. Once the structure is correct, CSS is straightforward and JavaScript has something solid to change.

Words you'll hear

Semantic HTML means choosing elements for their meaning, not their default appearance. A heading is a heading because it starts a section, not because it happens to be big. This matters for screen readers, search engines, and future you.

1.2 From a file to a page

When you double-click an HTML file, five things happen in order:

  1. You save

    A plain-text file ending in .html.

  2. Browser reads

    It reads the file from top to bottom.

  3. Builds the DOM

    A tree of elements: the Document Object Model.

  4. Lays out

    It calculates sizes and positions, then applies styles.

  5. Paints

    Pixels appear on your screen.

The DOM is the browser's live model of your page. You will hear this term constantly. For now, remember: your HTML becomes a tree, and JavaScript can change that tree after the page loads. That is how a static document becomes a to-do list or a game.

Local file, for now

Double-clicking the file is enough for this lesson. Later, when we load data from APIs, we will use a local server so the browser treats our files the same way it treats a real website. One thing at a time.

1.3 Tags, elements, attributes

HTML is written with tags. Most elements have three parts: an opening tag, some content, and a closing tag.

<p class="intro">Hello, world!</p>
PartIn the exampleWhat it does
Opening tag<p class="intro">Starts the element and names its type. Here: a paragraph.
Attributeclass="intro"Extra configuration. It lives inside the opening tag as a name–value pair.
ContentHello, world!The text or elements inside. This is what the paragraph contains.
Closing tag</p>Ends the element. Same name, with a forward slash.
ElementAll four parts togetherThe complete object: opening tag + content + closing tag.

Four rules that prevent most beginner bugs

  1. Close what you open. Every non-empty element needs a closing tag.
  2. Nest inside-out. The last tag opened must be the first one closed. <p><strong>Hi</strong></p> is correct. <p><strong>Hi</p></strong> is not.
  3. Quote attribute values. class="intro", not class=intro. Browsers may forgive it; humans and tools will not.
  4. Know the empty elements. A few elements have no content and no closing tag: <meta>, <img>, <br>. They are called void elements.
Common mistake

Browsers are forgiving — up to a point. A missing closing tag can make half your page disappear or nest inside the wrong element. The browser will guess. Its guess is often not what you meant. Check your structure early.

Memory tip: tags are bookends. Attributes are sticky notes on the front cover. The element is the whole book.

1.4 The skeleton every page needs

Every HTML5 page starts with the same outer shell. Type this until it becomes muscle memory.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, world!</h1>
  <p>This is my first webpage.</p>
</body>
</html>
Read this table once, then close it and try to write the skeleton from memory.
PartWhat it doesWhy it matters
<!DOCTYPE html>Tells the browser to use modern standards mode.Without it, browsers may render the page as if it were 1999.
<html lang="en">The root element. Wraps the document and declares its language.Screen readers pronounce content correctly. Search engines understand the page.
<head>Holds information about the page.Nothing in the head is visible in the page body.
<meta charset="UTF-8">Sets the character encoding.Prevents accents, symbols, and emoji from turning into garbage.
<meta name="viewport" …>Tells mobile browsers to use the device width.Without it, the page looks tiny and zoomed out on phones.
<title>Sets the text in the browser tab.Used by bookmarks, tabs, and search results.
<body>Holds everything the user can see.Headings, paragraphs, images, buttons, and footers all live here.

The document as a tree

Here is the same skeleton drawn as the DOM tree the browser builds. Notice that head and body are siblings inside html.

  • <html lang="en">
    • <head> backstage information
      • <meta charset="UTF-8">
      • <meta name="viewport" …>
      • <title>My First Page</title>
    • <body> what the visitor sees
      • <h1>Hello, world!</h1>
      • <p>This is my first webpage.</p>
Memory hook

Head = backstage. Body = the stage. If you want a visitor to see it, it goes in the body. If it is information for the browser, it goes in the head.

1.5 Headings and paragraphs

Headings are an outline, not a font-size menu. Use them to describe the importance and nesting of your content. CSS will control size later.

  • <h1> is the page's main topic. Use one per page.
  • <h2> marks major sections.
  • <h3> marks subsections inside an h2.
  • Do not jump from h1 to h4 because it looks better. That breaks the outline.
  • Do not use a heading just to make text big. Use CSS for visual size.
<h1>Maya's Learning Log</h1>
<p>I am learning <strong>HTML</strong>
because I want to build <em>my own</em>
websites.</p>

<h2>Today's win</h2>
<p>I wrote my first page from scratch.</p>
Browser result, before CSS

Today's win

<p> creates a paragraph. A paragraph is a distinct block of text, not just a line break. If you have two separate ideas, use two paragraphs.

<strong> marks importance. <em> marks emphasis, like a stressed word when speaking. Both change appearance by default — bold and italic — but their real value is the meaning. Do not use them simply to make text bold or italic; CSS does that job.

Memory hook

H1 is the book title. H2 is a chapter. H3 is a section inside the chapter. If your outline would confuse a reader, it will confuse a screen reader too.

Check it in the browser

  1. Save the file. Double-click it. Your browser should open a real page, not a code listing.
  2. Look at the browser tab. It should show your title.

  4. Resize the window narrow. The text should reflow. It will not be pretty yet — that is Module 2.

Your file is probably saved as about-me.html.txt or as an RTF/document file. In your editor, choose Save As, set the file type to All Files, and type the name with .html at the end. Then open it again.

1.8 Key things to remember

Six ideas that carry the whole course

  • HTML is structure and meaning. CSS is presentation. JavaScript is behavior.
  • The skeleton is non-negotiable: doctype → html → head + body.
  • An element is a unit: opening tag + content + closing tag. Attributes configure it from the opening tag.
  • Close tags inside-out. Last opened, first closed. Broken nesting causes invisible, confusing bugs.
  • One h1 per page. Headings are an outline; CSS is for visual size.
  • Head is backstage, body is the stage. If the visitor should see it, it belongs in the body.
