Module 05 · DOM & events

Selecting and changing the DOM

JavaScript becomes useful when it can read and change the page in front of you. The DOM is that page as a tree of objects: learn to select a node, change it, create one, and remove one without breaking the rest.

Lesson 5.1 60–75 min Beginner

By the end, you can

  • Select one element or many with CSS selectors.
  • Change text, classes, styles, and attributes safely.
  • Create, append, and remove elements.

You need

  • Your About Me page from Module 1.
  • Module 4: functions and arrays.
  • A browser with DevTools open.

The document is a tree

The browser turns your HTML into a tree of objects called the DOM. The global document object is the entrance. You search it with the same CSS selectors you already use in a stylesheet.

  • document.querySelector("h1") returns the first match, or null.
  • document.querySelectorAll(".card") returns every match as a NodeList.
  • IDs, classes, attributes, and descendant selectors all work: #app, .card, [data-open], nav a.

A NodeList from querySelectorAll supports forEach. If you need map or filter, convert it first with Array.from(buttons).

Guard the null

querySelector returns null when nothing matches. Check it before reading textContent, or you will get Cannot read properties of null.

Change text without breaking the page

textContent reads or writes plain text. It never parses HTML, so angle brackets appear as characters instead of becoming elements.

innerHTML parses a string as markup. That is useful when the string is yours. It is dangerous when the string contains something a visitor typed.

Safety rule

If the text came from a person, put it in with textContent or a text node. A string passed to innerHTML can contain elements and event handlers, which means it can run code.

Classes, styles, and attributes

Most visual changes belong in CSS. JavaScript should add, remove, or toggle a class, not hard-code a pile of styles.

CSS property names in a string use kebab-case; in the style object they use camelCase. Custom properties need setProperty("--name", value). Accessibility attributes such as aria-expanded belong in setAttribute.

Create, append, and remove

Build a new element with document.createElement, fill it, then attach it. A new node stays invisible until it is added to something already in the document.

append adds at the end, prepend adds at the start, and replaceChildren(...) swaps all children at once. Removing a node with remove() takes it out of the page, but your variable still points at it.

Exercise · 25 minutes

Highlight the headline, add a row

Assume the page contains <h1 id="title">, <ul id="list">, and one element with class="old". Write JavaScript that toggles the class is-highlighted on the headline, changes its text, creates a new li with text, appends it to the list, removes the old element, and logs how many items remain.

Make an attempt first. Then the model answer unlocks.

Check yourself

Why does querySelector sometimes return null?

No element matched the selector, or the script ran before the element existed. Check the selector in DevTools, and put the script after the markup or add the defer attribute.

When is innerHTML acceptable?

When the string is fixed markup that you wrote and control. Use textContent for names, comments, search terms, and anything else a person supplied.

Key things to remember

  • Select with CSS. querySelector gives one node; querySelectorAll gives a list.
  • Text is not markup. Use textContent for anything a visitor can type.
  • Build, then attach. Create an element, fill it, append it, and remove it when it is no longer needed.
