Module 07 · Ship it

Multi-page architecture

Three pages are a system, not three lucky guesses. Plan the folders, name the paths, and keep the shared shell consistent so every new page takes minutes instead of an afternoon.

Lesson 7.1 60–75 min Intermediate

By the end, you can

  • Lay out a small site in folders that still make sense in a month.
  • Write relative paths that work on your machine and on a host.
  • Keep one shared shell and show the active page in navigation.

You need

  • Your portfolio v1 from Module 2.
  • A code editor and a browser.
  • Two existing pages to connect.

Draw the map first

Decide what the site contains before you create files. Version 2 needs three pages: home, about, and projects. Everything else is an asset. A flat page layout with asset folders is easy to read and easy to deploy.

  • index.html is the default file for the folder. Hosts serve it automatically.
  • Keep all pages in one folder when there are only three. Deep folders add path mistakes before they add clarity.
  • Put styles, scripts, and images in their own folders so an asset can move without hunting through pages.
Name for the URL

Use lowercase file names with hyphens: projects.html, project-01.jpg. Some hosts are case-sensitive; Projects.html is a different file from projects.html.

Every page has one job

Shared structure makes a site feel like one place. Shared structure does not mean shared content. Each page needs one h1, a clear purpose, and a reason to exist beyond "another page".

PageJobProof it is done
index.htmlSay who you are and what you build.A clear h1, short intro, featured work.
about.htmlGive the story and the skills behind the work.A bio, a skills list, a contact link.
projects.htmlShow the work with enough context to understand it.At least three project entries with links.

The shell — skip link, header, navigation, footer — appears on every page. Only the middle changes. When you edit the navigation, edit all three pages in the same pass. The same rule applies to the footer.

aria-current="page" is the accessible active state. Do not rely on color alone. Move the attribute to the link for the page the visitor is on; the CSS can style it.

The script above is a convenience, not a requirement. Hard-coding the attribute is more robust and easier to understand while you are learning. Use the script only after the static version works.

Relative paths are a contract

A relative path resolves from the file that contains it. From index.html, projects.html is a sibling; from css/styles.css, an image is ../images/portrait.jpg.

FromToWrite
index.htmlabout.htmlabout.html
projects.htmlthe stylesheetcss/styles.css
about.htmlthe home pageindex.html
css/styles.cssimages/portrait.jpg../images/portrait.jpg
Skip the leading slash

Do not start internal links with / unless you know the site lives at the domain root. GitHub Pages project sites live under /repository-name/, so /about.html breaks there. Keep paths relative.

Separate the layers

Inline styles and inline scripts are fine for a demo and painful across three pages. Keep one stylesheet and one script. Link them from each page using paths relative to that page.

  • One stylesheet means one color palette, one spacing scale, one place to fix a mobile bug.
  • One script with defer runs after the HTML is parsed. It can safely find elements on the page.
  • When the site grows past a handful of pages, reach for a static site generator or web components. Do not add a framework just to avoid three copies of a header.
Exercise · 30 minutes

Plan a three-page site

Write the folder tree for index.html, about.html, and projects.html, plus css/styles.css, js/main.js, and an images/ folder. List the relative link from each page to the other two and to both assets. Then write the navigation markup with projects.html active.

Make an attempt first. Then the model answer unlocks.

Check yourself

Why do root-relative links like /about.html break on GitHub Pages?

A project site is served from /repository-name/, not the domain root. /about.html points above the project; about.html resolves from the current page.

How do I avoid copying the header into every page?

In plain static HTML you cannot include one file directly. Keep the markup identical, change only the active link, and keep all styling in one stylesheet. When the site grows, use a static site generator or a component system instead of a framework you do not need.

Key things to remember

  • Plan the map first. Pages, assets, and names before markup.
  • Paths are relative to the file. Test every link from every page.
  • One shell, one stylesheet, one script. Duplication is a maintenance bug.
