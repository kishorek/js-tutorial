Type, color, and visual rhythm

Good styling is mostly a few decisions repeated consistently: a readable type scale, a small palette with enough contrast, and spacing that comes from one system. This lesson turns those decisions into tokens you can reuse.

Type starts with a system

A font stack lists the fonts you want, best first, and ends with a generic family. Use a system stack for fast, native-looking text. Set body size in rem, keep line-height unitless, and use weight to create hierarchy before you reach for a new size.

  • rem is relative to the root font size. Use it for page-level sizes so a user's browser preference is respected.
  • em is relative to the current element's font size. Use it when a component should scale as a whole.
  • Unitless line-height such as 1.6 scales with the font instead of locking to pixels. Body text usually sits between 1.4 and 1.7; headings between 1.05 and 1.3.
  • Weight is a quick hierarchy tool: 400 body, 600 or 700 headings. Do not use a light weight for small text.

A type scale is a short list of sizes with a consistent ratio. Pick four or five steps and stop. Fewer sizes make the page calmer and the code easier to change.

Color needs contrast, not just taste

Text must stay readable for people with low vision, on a phone in daylight, and on a cheap monitor. WCAG asks for a contrast ratio of at least 4.5:1 for normal text and 3:1 for large text (about 24px, or 18.66px bold). Muted text still has to pass; "soft gray" is not an excuse.

Do not rely on color alone

If an error is red, also include a message or an icon. If a link is green, underline it on hover and focus. Color is a reinforcement, not the only signal. Check every pair with a contrast tool before shipping.

Keep the palette small: an ink for text, a muted ink for secondary text, a page background, a card background, one accent, and one rule color. A restrained palette makes a single accent feel deliberate.

Tokens create visual rhythm

CSS custom properties (variables) store a decision once and reuse it. Define them on :root so the whole page inherits them, then reference them with var(). Change the token, and every component follows.

Custom property names are case-sensitive and inherit like other properties. A fallback such as var(--accent, #14532d) keeps a component usable if the token is missing. For depth, one thin border plus one soft shadow is enough; save large shadows for overlays. Always keep a visible :focus-visible outline.

Check yourself

When should I use rem instead of em?

Use rem for the page's type scale and global spacing so it follows the root size and user preferences. Use em inside a component when padding or a nested size should scale with that component's own font size.

Is gray text on a white background always a contrast problem?

Not always, but it often is. The ratio matters, not the color name. Check the exact pair: normal text needs 4.5:1. A medium gray such as #5d574d on #f7f2e7 can pass while a pale gray fails.

Key things to remember

  • Type is a scale. A few rem sizes and unitless line-heights beat a pile of one-off values.
  • Contrast is a requirement. Check text pairs, and never use color as the only signal.
  • Tokens make rhythm repeatable. Store color, type, and spacing decisions once on :root.
