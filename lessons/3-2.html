Module 03 · Layout & responsive design

Mobile-first responsive design

A responsive page is not three separate layouts. It is one layout that starts small, then gains columns and scale as the screen earns the space. Mobile-first keeps that logic in the order you write the CSS.

By the end, you can

  • Write min-width media queries that add layout.
  • Choose breakpoints from content, not device names.
  • Use clamp() and responsive images safely.

You need

  • Lesson 3.1: CSS Grid.

Start with the viewport

Without a viewport meta tag, a phone pretends its screen is about 980px wide and shrinks the result. Your page looks like a desktop site photographed from far away, and every media query fires at the wrong size.

Put it in head on every page. The first part makes the layout width equal the device width; the second sets the initial zoom to normal. Do not add user-scalable=no. Zoom is an accessibility feature.

Layer styles with min-width

Mobile-first means the base CSS describes the narrow layout. Media queries then add complexity only when there is room. Because both rules have the same specificity, the later min-width block wins when the condition is true.

Compare that with a desktop-first rule using max-width. The base styles assume a wide screen, then undo columns as the screen shrinks. It works, but you spend the narrow case overriding decisions instead of defining them.

Breakpoints follow the content

Do not choose breakpoints by naming phones and tablets. Resize the browser slowly and add a breakpoint where the layout stops working: a line of text gets too long, cards get too narrow, or navigation wraps badly.

  • Write the breakpoint at the width just before the problem appears.
  • em-based queries scale with the user's font settings: 48em is usually a better choice than 768px.
  • Most projects need two or three breakpoints, not one per device.
  • Test the gap between breakpoints, not only the exact values.

Fluid type reduces the number of queries you need. clamp(minimum, preferred, maximum) lets a value grow with the viewport but never outside the limits you set.

The middle value does the fluid work; the outer values keep the result readable. Use clamp() for headings and large spacing, not for every value. Body text should stay near 1rem.

Images and horizontal overflow

An image wider than its container is the most common cause of sideways scrolling. Make images behave by default.

  • max-width: 100% and height: auto keep the aspect ratio while fitting the column.
  • srcset and sizes let the browser download a file that matches the space it will occupy.
  • Always keep width and height attributes to reserve space and reduce layout shift.
  • Use object-fit: cover when a fixed aspect ratio matters; the image crops instead of squashing.
Do not hide the problem

overflow-x: hidden on body makes sideways scrolling disappear without fixing what caused it. Find the wide element in DevTools, then correct its sizing. Reserve overflow clipping for intentional decorative bleed.

Write mobile-first CSS for a .split section with two children. Below 700px the children stack in one column with a 1.5rem gap. At 700px and wider they sit in two equal columns with a 2.5rem gap. Use minmax(0, 1fr) so long content cannot widen the page.

Check yourself

Why is a min-width query usually better than max-width?

It lets the small-screen layout be the default and adds rules only when space exists. That keeps the CSS shorter and reduces the chance that a narrow screen inherits a desktop assumption.

Does clamp() remove the need for media queries?

No. It scales values smoothly, but it cannot rearrange a grid, change navigation, or reorder content. Use clamp() for size and media queries for structure.

Key things to remember

  • Viewport first. Without the meta tag, every responsive decision is measured against the wrong width.
  • Small screens are the default. Use min-width to add columns and spacing.
  • Test content, not device names. Check 320, 768, and 1440, and fix the cause of overflow instead of hiding it.
