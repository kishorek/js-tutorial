fetch, JSON, and API keys

Your page can ask another computer for data. Learn the request/response cycle, how fetch and JSON fit together, and why secret keys must never ship in browser code.

A request goes out, a response comes back

An API is a contract: you send an HTTP request to a URL, and a server sends back a response. The request has a method, such as GET to read data or POST to send it. The response has a status code, headers, and usually a body.

StatusMeaningWhat to do
200SuccessRead the body.
400Bad requestFix the URL or parameters.
401Not authorizedAdd valid credentials on the server.
404Not foundCheck the path or search term.
429Too many requestsSlow down or cache results.
500Server errorRetry later; it is not your URL.

Most modern APIs send JSON: text that looks like JavaScript objects and arrays. A weather response might contain a nested current object with a temperature and a weather code.

fetch returns a promise

fetch() starts a request and returns a promise. The promise resolves as soon as the response headers arrive, even for a 404. That is why you must check response.ok before reading the body.

response.json() is asynchronous too. It reads the body and parses the JSON text into JavaScript values, so it also needs await. If the body is not valid JSON, it rejects.

fetch does not reject on 404

A network failure rejects the promise. An HTTP error such as 404 or 500 still fulfills it. Always check response.ok, or you will try to parse an error page as data.

Build the URL with query parameters

Query parameters are the key=value pairs after the ?. They filter a search, choose fields, or set options. Separate them with & and encode user input with encodeURIComponent().

Open-Meteo needs two steps. First, geocoding turns a city name into coordinates. Then the forecast endpoint uses those coordinates. Both are free and need no key.

CORS is the browser's rule for cross-origin requests. If the API does not send the right Access-Control-Allow-Origin header, the browser blocks your code from reading the response. You cannot fix that in client JavaScript; the API must allow your origin, or you need a server proxy.

Reading a CORS error

The request may appear in the Network panel with a response, while the console reports a CORS failure. The browser received data but refused to expose it to your page.

API keys stay on the server

Some APIs use a key to identify and bill the caller. A public key is designed to be visible and restricted by domain. A secret key is not. Anything in HTML, CSS, or client JavaScript can be read by every visitor.

Hiding a key in a variable, a comment, or an obfuscated file is not security. The browser must send the key with the request, so it is visible in DevTools. A secret key in client code can be copied and used against your account.

When a key is required, put it in a small server or serverless function. The key lives in an environment variable on the server. Your browser calls your endpoint; your endpoint calls the API and returns only the data the page needs.

Never commit a key

Do not put secrets in a public repository, a screenshot, or a shared chat. If a secret key leaks, revoke it and create a new one. Open-Meteo needs no key, which makes it a safe place to practise.

Check yourself

Why does a 404 response not throw by itself?

The fetch promise rejects only when the request cannot be completed, such as a network failure. An HTTP 404 is still a completed response, so the promise fulfills. Check response.ok and throw your own error when it is false.

If a key is hidden in a JavaScript variable, is it safe?

No. The browser must send the key to the API, so it appears in DevTools, source files, or the Network panel. Secret keys belong on a server, read from environment variables, behind an endpoint your page can call.

Key things to remember

  • fetch is asynchronous. Await the response, check response.ok, then await response.json().
  • URLs carry the request. Encode user input and use query parameters for search terms and options.
  • CORS and keys are server concerns. A blocked response needs an API or proxy that allows your origin; secrets never belong in the browser.
