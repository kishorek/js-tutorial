Loading, empty, and error states

Network request slow-ஆ இருக்கலாம், எதுவும் return பண்ணாம இருக்கலாம், இல்ல fail ஆகலாம். நல்ல interface எல்லா நேரத்துலயும் உண்மையைச் சொல்லணும். நாலு states-ஐ model பண்ணி, யூகிக்காம render பண்ண கத்துக்கொள்ளுங்கள்.

Name the four states

நிறைய data-driven interfaces-க்கு நாலு states இருக்கும். Success state-ஐ மட்டும் build பண்ணா, ஒவ்வொரு slow request-ம் broken மாதிரியும், ஒவ்வொரு failure-ம் frozen மாதிரியும் தெரியும்.

StateMeaningWhat the user sees
LoadingRequest இன்னும் run ஆகிக்கொண்டிருக்கு.சின்ன status message இல்ல skeleton; controls disabled.
EmptyRequest success ஆனது, ஆனா எதுவும் கிடைக்கல.அடுத்த step-ஓட தெளிவான "no results" message.
ErrorRequest fail ஆனது இல்ல timeout ஆனது.Simple language message-ம் retry action-ம்.
SuccessData வந்துட்டு, ready-ஆ இருக்கு.Actual content, data-லேர்ந்து render பண்ணப்பட்டது.

முதல் request-க்கு முன்னாடி idleனு ஐந்தாவது, அமைதியான state-ம் இருக்கு. அதை "இன்னும் எதுவும் நடக்கல"-னு treat பண்ணி சின்ன instruction காட்டுங்கள். Empty message-ஐ மறுபடி use பண்ணாதீங்க; search-க்கு முன்னாடி "no results" confuse பண்ணும்.

Render from one state object

State-ஐ ஒரே object-ல வையுங்கள், screen என்ன காட்டணும்-னு ஒரே render() function decide பண்ணட்டும். UI அப்போ state-ன் function ஆகும், தொடர்பில்லாத DOM changes-ன் குவியலா இருக்காது.

ஒவ்வொரு transition-ம் setState() வழியா போகணும்: loading set பண்ணி, பிறகு success, empty, இல்ல error. அதனால screen update பண்ண ஒரே இடமும், debug பண்ண ஒரே இடமும் கிடைக்கும்.

Clear stale data

புது request start ஆகும்போது, பழைய result-ஐ screen-ல வைக்கணுமா-னு decide பண்ணுங்கள். சின்ன weather card-க்கு, loading message-க்கு பக்கத்துல நேத்து temperature காட்டாம இருக்க அதை clear பண்ணது நல்லது.

Catch errors and show something useful

Request-ஐ try/catch-ல wrap பண்ணுங்கள். response.ok false-ஆ இருக்கும்போது உங்க சொந்த error-ஐ throw பண்ணுங்கள். Technical detail-ஐ உங்களுக்காக log பண்ணுங்கள், ஆனா user-க்கு அவங்க action எடுக்கக்கூடிய message-ஐ காட்டுங்கள்.

Timeout ஒரு AbortController-ஐ use பண்ணும். Timer fire ஆனதும், controller.abort() request-ஐ cancel பண்ணும், catch block AbortError-னு பேர் இருக்குற error-ஐ பார்க்கும். finally block request success ஆனாலும் fail ஆனாலும் timer-ஐ clear பண்ணும்.

Retry button கடைசி city-ஓட அதே load() function-ஐ call பண்ணணும். Loading-ல இருக்கும்போது அதை disable பண்ணுங்கள், double click ரெண்டு requests start பண்ணாம இருக்க. Failure 404-ஆ இருந்தா retry உதவாது; search-ஐ மாத்த சொல்லுங்கள்.

Do not swallow the error

காலியான catch block bug-ஐ hide பண்ணி, user-ஐ blank screen-ஐ பார்த்துக்கிட்டு விட்டுடும். எப்பவும் UI-ஐ error state-க்கு மாத்தி, debugging-க்கு original error-ஐ log பண்ணுங்கள்.

Announce changes with aria-live

Screen reader users-க்கு spinner வரது தெரியாது. Status area-ஐ live region-ஆ mark பண்ணுங்கள், focus-ஐ நகர்த்தாம changes announce ஆகும்.

role="status" ஏற்கனவே polite live region-ஐ imply பண்ணும். Region-ஐ சின்னதா வையுங்கள்: மாறுற message-ஐ அதுக்குள்ள வையுங்கள், முழு page-ஐயும் அல்ல. வழக்கமான loading updates-க்கு aria-live="assertive"-ஐ தவிர்க்கவும், ஏன்னா அது user படிக்குறதை interrupt பண்ணும்.

Error வரும்போது, message visible-ஆவும் live region-லயும் இருக்கணும். Retry button வந்தா, "Try again" மாதிரி ஒரு real label கொடுங்கள், accessible name இல்லாத icon-ஐ அல்ல.

Check yourself

What is the difference between the empty and error states?

Empty-னா request work ஆனது, ஆனா match ஆன data எதுவும் return ஆகல — தெரியாத city மாதிரி. Error-னா request சரியா complete ஆகல. Empty பொதுவா வேற search கேட்கும்; error பொதுவா retry offer பண்ணும்.

Why clear the timeout in a finally block?

Fast response வந்த பிறகு timer fire ஆகக்கூடாது. finally success-லயும் failure-லயும் run ஆகும், அதனால pending timeout-ஐ cancel பண்ணி அப்புறம் stray abort வராம தடுக்க இது நம்பகமான இடம்.

Key things to remember

  • State-ஐ model பண்ணி, அப்புறம் render பண்ணுங்கள். Loading, empty, error, success — ஒவ்வொண்ணுக்கும் ஒரு design பண்ணின screen இருக்கணும்.
  • Failures-க்கு அடுத்த step வேணும். Simple language message காட்டி, technical error-ஐ log பண்ணி, உதவும்போது retry offer பண்ணுங்கள்.
  • Changes-ஐ announce பண்ணுங்கள். சின்ன polite live region screen reader users-ஐ focus-ஐ பிடுங்காம inform-ஆ வைக்கும்.
