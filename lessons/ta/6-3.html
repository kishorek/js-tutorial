தொகுதி 06 · Async & APIs

Loading, empty, மற்றும் error நிலைகள்

Network request மெதுவாக இருக்கலாம், எதையும் திருப்பித் தராமல் இருக்கலாம், அல்லது தோல்வியடையலாம். நல்ல interface ஒவ்வொரு நேரத்திலும் உண்மையைச் சொல்லும். நான்கு நிலைகளை model செய்து, ஊகிக்காமல் render செய்யக் கற்றுக்கொள்ளுங்கள்.

பாடம் 6.3 60–75 நிமிடம் தொடக்கநிலை

இந்தப் பாடம் முடியும்போது, நீங்கள்:

  • நான்கு UI நிலைகளைப் பெயரிட்டு model செய்யுங்கள்.
  • ஒரே state object-ல் இருந்து render செய்யுங்கள்.
  • பயனுள்ள errors காட்டி retry வழங்குங்கள்.
  • aria-live மூலம் updates-ஐ அறிவியுங்கள்.

உங்களுக்குத் தேவை

  • பாடம் 6.2 fetch மற்றும் JSON.
  • update செய்ய ஒரு element உள்ள page.
  • failures-ஐ test செய்யும்போது DevTools திறந்திருக்க வேண்டும்.

நான்கு நிலைகளுக்குப் பெயரிடுங்கள்

பெரும்பாலான data-driven interfaces-க்கு நான்கு நிலைகள் உண்டு. Success நிலையை மட்டும் உருவாக்கினால், ஒவ்வொரு மெதுவான request-ம் broken போலவும், ஒவ்வொரு failure-ம் frozen போலவும் தெரியும்.

நிலைபொருள்User என்ன பார்ப்பார்
LoadingRequest இன்னும் நடந்துகொண்டிருக்கிறது.சிறிய status message அல்லது skeleton; controls disabled.
EmptyRequest வெற்றியடைந்தது, ஆனால் எதுவும் கிடைக்கவில்லை.அடுத்த step உடன் "முடிவுகள் இல்லை" என்ற தெளிவான message.
ErrorRequest தோல்வியடைந்தது அல்லது timeout ஆனது.எளிய மொழியில் message மற்றும் retry action.
SuccessData வந்துவிட்டது, தயாராக உள்ளது.Data-வில் இருந்து render செய்யப்பட்ட உண்மையான content.

முதல் request-க்கு முன், idle என்ற ஐந்தாவது, அமைதியான நிலையும் உண்டு. அதை "இன்னும் எதுவும் நடக்கவில்லை" என்று கருதி, சிறிய instruction காட்டுங்கள். Empty message-ஐ மீண்டும் பயன்படுத்த வேண்டாம்; search-க்கு முன் "முடிவுகள் இல்லை" என்பது குழப்பமாக இருக்கும்.

ஒரே state object-ல் இருந்து render செய்யுங்கள்

State-ஐ ஒரே object-ல் வைத்து, screen என்ன காட்ட வேண்டும் என்பதை ஒரே render() function முடிவு செய்யட்டும். UI, தொடர்பில்லாத DOM மாற்றங்களின் குவியலாக அல்லாமல் state-ன் function ஆக மாறும்.

ஒவ்வொரு transition-ம் setState() வழியாகவே செல்லும்: loading அமைத்து, பிறகு success, empty, அல்லது error. இது screen-ஐ update செய்ய ஒரே இடத்தையும், debug செய்ய ஒரே இடத்தையும் தரும்.

பழைய data-ஐ அழிக்கவும்

புதிய request தொடங்கும்போது, பழைய முடிவைத் தெரியும்படி வைத்திருக்கலாமா என்று முடிவு செய்யுங்கள். சிறிய weather card-க்கு, loading message-க்கு அருகில் நேற்றைய temperature தெரியாமல் இருக்க அதை அழிப்பது நல்லது.

Errors-ஐப் பிடித்து பயனுள்ள ஒன்றைக் காட்டுங்கள்

Request-ஐ try/catch-ல் வையுங்கள். response.ok false ஆகும்போது உங்கள் சொந்த error-ஐ throw செய்யுங்கள். தொழில்நுட்ப விவரங்களை உங்களுக்காக log செய்யுங்கள், ஆனால் user-க்கு அவர் செயல்படக்கூடிய message-ஐக் காட்டுங்கள்.

Timeout AbortController-ஐப் பயன்படுத்துகிறது. Timer fire ஆனதும், controller.abort() request-ஐ ரத்து செய்யும்; AbortError என்ற error-ஐ catch block பார்க்கும். Request வெற்றியடைந்தாலும் தோல்வியடைந்தாலும் finally block timer-ஐ clear செய்யும்.

Retry button அதே load() function-ஐ கடைசி city உடன் அழைக்க வேண்டும். Loading-ல் இருக்கும்போது அதை disable செய்யுங்கள்; இல்லையென்றால் double click இரண்டு requests தொடங்கும். தோல்வி 404 என்றால் retry உதவாது; அதற்குப் பதிலாக search-ஐ மாற்றச் சொல்லுங்கள்.

Error-ஐ மௌனமாக விழுங்க வேண்டாம்

காலியான catch block bug-ஐ மறைத்து, user-ஐ வெறும் blank screen-ஐப் பார்க்க வைக்கும். எப்போதும் UI-ஐ error நிலைக்கு மாற்றி, debug செய்ய அசல் error-ஐ log செய்யுங்கள்.

aria-live மூலம் மாற்றங்களை அறிவியுங்கள்

Screen reader users-க்கு spinner தோன்றுவது தெரியாது. Focus-ஐ நகர்த்தாமல் மாற்றங்கள் அறிவிக்கப்பட, status area-ஐ live region ஆகக் குறியுங்கள்.

role="status" ஏற்கனவே polite live region-ஐக் குறிக்கிறது. Region-ஐச் சிறியதாக வையுங்கள்: மாறும் message-ஐ அதற்குள் வையுங்கள், முழு page-ஐ அல்ல. வழக்கமான loading updates-க்கு aria-live="assertive"-ஐத் தவிர்க்கவும்; அது user படிப்பதை இடையூறு செய்யும்.

Error தோன்றும்போது, message தெரியும்படியும் live region-ல் இருக்கும்படியும் பாருங்கள். Retry button தோன்றினால், "மீண்டும் முயலுங்கள்" போன்ற உண்மையான label கொடுங்கள்; accessible name இல்லாத icon கொடுக்காதீர்கள்.

Fake fetch-க்கு மூன்று நிலைகளை render செய்யுங்கள்

state object மற்றும் id="output" உள்ள element-ஐ update செய்யும் render() function உருவாக்குங்கள். சுமார் 700 ms கழித்து temperature உடன் resolve ஆகவோ, reject ஆகவோ fakeFetch() எழுதுங்கள். loading அமைத்து, render() அழைத்து, fetch-க்காக await செய்து, பிறகு success அல்லது error அமைத்து மீண்டும் render செய்ய load() எழுதுங்கள். try/catch பயன்படுத்துங்கள்.

முதலில் ஒரு முயற்சி செய்யுங்கள். பிறகு மாதிரி விடை திறக்கும்.

உங்களைச் சரிபாருங்கள்

Empty மற்றும் error நிலைகளுக்கு இடையிலான வேறுபாடு என்ன?

Empty என்றால் request வேலை செய்தது, ஆனால் பொருந்தும் data எதுவும் திரும்பி வரவில்லை; உதாரணமாகத் தெரியாத city. Error என்றால் request சரியாக முடியவில்லை. Empty பொதுவாக வேறு search கேட்கும்; error பொதுவாக retry வழங்கும்.

finally block-ல் timeout-ஐ ஏன் clear செய்ய வேண்டும்?

விரைவான response-க்குப் பிறகு timer fire ஆகக்கூடாது. finally வெற்றி, தோல்வி இரண்டிலும் இயங்கும், எனவே நிலுவையில் உள்ள timeout-ஐ ரத்து செய்து பின்னர் தேவையற்ற abort-ஐத் தவிர்க்க இதுவே நம்பகமான இடம்.

நினைவில் கொள்ள வேண்டிய முக்கிய விஷயங்கள்

  • State-ஐ model செய்து, பிறகு render செய்யுங்கள். Loading, empty, error, success ஒவ்வொன்றுக்கும் வடிவமைக்கப்பட்ட screen இருக்க வேண்டும்.
  • தோல்விகளுக்கு அடுத்த step தேவை. எளிய மொழியில் message காட்டி, தொழில்நுட்ப error-ஐ log செய்து, உதவும்போது retry வழங்குங்கள்.
  • மாற்றங்களை அறிவியுங்கள். சிறிய polite live region, focus-ஐ எடுத்துக்கொள்ளாமல் screen reader users-க்குத் தகவல் தரும்.
