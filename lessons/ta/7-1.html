தொகுதி 07 · வெளியிடு

பல பக்க கட்டமைப்பு

மூன்று பக்கங்கள் என்பது ஒரு அமைப்பு; மூன்று அதிர்ஷ்டமான யூகங்கள் அல்ல. Folder-களைத் திட்டமிடுங்கள், பாதைகளுக்குப் பெயரிடுங்கள், பகிரப்பட்ட shell-ஐ ஒரே மாதிரியாக வைத்திருங்கள் — அப்போது புதிய ஒவ்வொரு பக்கமும் ஒரு மதியத்திற்குப் பதிலாக சில நிமிடங்களில் முடியும்.

பாடம் 7.1 60–75 நிமிடம் இடைநிலை

இதன் முடிவில், நீங்கள்

  • ஒரு மாதம் கழித்தும் புரியும் வகையில் சிறிய தளத்தை folder-களில் அமைக்க முடியும்.
  • உங்கள் கணினியிலும் host-இலும் வேலை செய்யும் சார்புப் பாதைகளை எழுத முடியும்.
  • ஒரே பகிரப்பட்ட shell-ஐ வைத்து, navigation-ல் தற்போதைய பக்கத்தைக் காட்ட முடியும்.

உங்களுக்குத் தேவை

  • தொகுதி 2-ல் நீங்கள் உருவாக்கிய portfolio v1.
  • ஒரு code editor மற்றும் ஒரு browser.
  • இணைக்க ஏற்கனவே உள்ள இரண்டு பக்கங்கள்.

முதலில் வரைபடத்தை வரையுங்கள்

கோப்புகளை உருவாக்கும் முன், தளத்தில் என்ன இருக்க வேண்டும் என்பதை முடிவு செய்யுங்கள். பதிப்பு 2-க்கு மூன்று பக்கங்கள் தேவை: home, about, projects. மற்ற எல்லாமே asset. பக்கங்களை ஒரே நிலையில் வைத்து, asset-களுக்குத் தனி folder-கள் கொடுத்தால் படிக்கவும் எளிது, deploy செய்யவும் எளிது.

  • index.html என்பது folder-இன் இயல்புநிலைக் கோப்பு. Host-கள் அதைத் தானாகவே வழங்கும்.
  • மூன்று பக்கங்கள் மட்டுமே இருக்கும்போது எல்லாப் பக்கங்களையும் ஒரே folder-ல் வையுங்கள். ஆழமான folder-கள் தெளிவைக் கூட்டுவதற்கு முன் பாதைத் தவறுகளைக் கூட்டும்.
  • Styles, scripts, images-க்கு தனித்தனி folder-கள் கொடுங்கள்; அப்போது ஒரு asset-ஐ நகர்த்தும்போது பக்கங்களில் தேட வேண்டியதில்லை.
URL-க்கு ஏற்ற பெயர்

சிறிய எழுத்துக்களில், hyphen உடன் கோப்புப் பெயர்களை வைக்கவும்: projects.html, project-01.jpg. சில host-கள் case-sensitive; Projects.html என்பது projects.html-இலிருந்து வேறு கோப்பு.

ஒவ்வொரு பக்கத்திற்கும் ஒரு வேலை

பகிரப்பட்ட அமைப்பு தளத்தை ஒரே இடமாக உணர வைக்கும். பகிரப்பட்ட அமைப்பு என்பது பகிரப்பட்ட உள்ளடக்கம் அல்ல. ஒவ்வொரு பக்கத்திற்கும் ஒரு h1, தெளிவான நோக்கம், "இன்னொரு பக்கம்" என்பதைத் தாண்டிய இருக்கக் காரணம் தேவை.

பக்கம்வேலைமுடிந்ததற்கான அடையாளம்
index.htmlநீங்கள் யார், என்ன உருவாக்குகிறீர்கள் என்பதைச் சொல்லும்.தெளிவான h1, சிறு அறிமுகம், சிறப்பு வேலைகள்.
about.htmlவேலைக்குப் பின்னால் உள்ள கதையையும் திறன்களையும் சொல்லும்.ஒரு bio, திறன் பட்டியல், தொடர்பு இணைப்பு.
projects.htmlபுரிந்துகொள்ளத் தேவையான சூழலுடன் வேலையைக் காட்டும்.இணைப்புகளுடன் குறைந்தது மூன்று project பதிவுகள்.

shell — skip link, header, navigation, footer — ஒவ்வொரு பக்கத்திலும் தோன்றும். நடுப்பகுதி மட்டுமே மாறும். Navigation-ஐத் திருத்தும்போது, மூன்று பக்கங்களையும் ஒரே நேரத்தில் திருத்துங்கள். footer-க்கும் இதே விதி.

aria-current="page" என்பது அணுகல்தன்மையுடைய active நிலை. நிறத்தை மட்டும் நம்பாதீர்கள். பார்வையாளர் இருக்கும் பக்கத்தின் இணைப்பிற்கு இந்த attribute-ஐ நகர்த்துங்கள்; CSS அதை style செய்யும்.

மேலே உள்ள script ஒரு வசதி, கட்டாயம் அல்ல. கற்றுக்கொள்ளும்போது attribute-ஐ நேரடியாக எழுதுவது மிகவும் உறுதியானது, புரிந்துகொள்ள எளிதானது. Static version வேலை செய்த பிறகே script-ஐப் பயன்படுத்துங்கள்.

சார்புப் பாதைகள் ஒரு ஒப்பந்தம்

சார்புப் பாதை அது இருக்கும் கோப்பிலிருந்தே தொடங்குகிறது. index.html-இலிருந்து projects.html அதே folder-ல் உள்ளது; css/styles.css-இலிருந்து ஒரு படத்தின் பாதை ../images/portrait.jpg.

எங்கிருந்துஎங்கேஎழுதுவது
index.htmlabout.htmlabout.html
projects.htmlstylesheetcss/styles.css
about.htmlமுகப்புப் பக்கம்index.html
css/styles.cssimages/portrait.jpg../images/portrait.jpg
முன்னால் வரும் slash-ஐத் தவிர்க்கவும்

தளம் domain root-ல் இருக்கிறது என்று தெரியாவிட்டால், உள் இணைப்புகளை /-ல் தொடங்காதீர்கள். GitHub Pages project தளங்கள் /repository-name/-ல் இருக்கும்; அங்கே /about.html வேலை செய்யாது. பாதைகளைச் சார்பாகவே வைத்திருங்கள்.

அடுக்குகளைப் பிரிக்கவும்

Demo-க்கு inline styles, inline scripts பரவாயில்லை; மூன்று பக்கங்களில் அவை சிரமம். ஒரு stylesheet, ஒரு script மட்டும் வைத்திருங்கள். ஒவ்வொரு பக்கத்திலிருந்தும் அந்தப் பக்கத்திற்குச் சார்பான பாதைகளில் அவற்றை இணைக்கவும்.

  • ஒரு stylesheet என்றால் ஒரு color palette, ஒரு spacing scale, mobile bug-ஐ சரிசெய்ய ஒரே இடம்.
  • defer உடன் ஒரு script, HTML parse ஆன பிறகு இயங்கும். பக்கத்தில் உள்ள element-களை பாதுகாப்பாகக் கண்டறியும்.
  • தளம் சில பக்கங்களைத் தாண்டி வளரும்போது static site generator அல்லது web components-ஐப் பயன்படுத்துங்கள். header-இன் மூன்று copies-ஐத் தவிர்க்க மட்டும் ஒரு framework சேர்க்காதீர்கள்.
பயிற்சி · 30 நிமிடம்

மூன்று பக்க தளத்தைத் திட்டமிடுங்கள்

index.html, about.html, projects.html ஆகியவற்றுக்கான folder tree-ஐ எழுதுங்கள்; அத்துடன் css/styles.css, js/main.js, மற்றும் images/ folder-ஐயும். ஒவ்வொரு பக்கத்திலிருந்தும் மற்ற இரண்டு பக்கங்களுக்கும், இரண்டு asset-களுக்கும் உள்ள சார்பு இணைப்புகளைப் பட்டியலிடுங்கள். பிறகு projects.html active-ஆக இருக்கும் வகையில் navigation markup எழுதுங்கள்.

முதலில் முயற்சி செய்யுங்கள். பிறகு மாதிரி விடை திறக்கும்.

உங்களைச் சோதித்துக் கொள்ளுங்கள்

GitHub Pages-ல் /about.html போன்ற root-relative இணைப்புகள் ஏன் வேலை செய்யாது?

Project தளம் domain root-இலிருந்து அல்ல, /repository-name/-இலிருந்து வழங்கப்படுகிறது. /about.html project-க்கு மேலே சுட்டுகிறது; about.html தற்போதைய பக்கத்திலிருந்து தொடங்குகிறது.

ஒவ்வொரு பக்கத்திலும் header-ஐ copy செய்வதை எப்படித் தவிர்ப்பது?

சாதாரண static HTML-ல் ஒரு கோப்பை நேரடியாக include செய்ய முடியாது. Markup-ஐ ஒரே மாதிரி வைத்திருங்கள், active இணைப்பை மட்டும் மாற்றுங்கள், எல்லா styling-ஐயும் ஒரே stylesheet-ல் வைத்திருங்கள். தளம் வளரும்போது, தேவையில்லாத framework-க்குப் பதிலாக static site generator அல்லது component system பயன்படுத்துங்கள்.

நினைவில் வைக்க வேண்டிய முக்கிய விஷயங்கள்

  • முதலில் வரைபடத்தைத் திட்டமிடுங்கள். Markup-க்கு முன் பக்கங்கள், assets, பெயர்கள்.
  • பாதைகள் கோப்பிற்குச் சார்பானவை. ஒவ்வொரு பக்கத்திலிருந்தும் ஒவ்வொரு இணைப்பையும் சோதியுங்கள்.
  • ஒரு shell, ஒரு stylesheet, ஒரு script. நகலெடுப்பது ஒரு maintenance bug.
