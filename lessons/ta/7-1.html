Multi-page architecture

மூன்று pages-ஐ ஒரு system-ஆ பார்க்கணும், மூன்று யூகங்களா இல்ல. Folders-ஐ plan பண்ணுங்கள், paths-க்கு பெயர் வையுங்கள், shared shell-ஐ ஒரே மாதிரி வைத்திருங்கள் — அப்போ புது page ஒவ்வொன்றும் ஒரு மதியம் எடுக்காம சில நிமிடங்கள்ல முடியும்.

Lesson 7.1 60–75 min Intermediate

By the end, you can

  • ஒரு மாதம் கழிச்சும் புரியும் folders-ல சின்ன site-ஐ அமைக்க முடியும்.
  • உங்கள் machine-லயும் host-லயும் வேலை செய்யிற relative paths எழுத முடியும்.
  • ஒரே shared shell-ஐ வெச்சு, navigation-ல active page-ஐ காட்ட முடியும்.

You need

  • Module 2-ல நீங்கள் build பண்ணின portfolio v1.
  • ஒரு code editor-உம் ஒரு browser-உம்.
  • Connect பண்ண இருக்கிற இரண்டு pages.

Draw the map first

Files-ஐ create பண்ணுறதுக்கு முன்னாடி, site-ல என்ன இருக்கணும்-னு decide பண்ணுங்கள். Version 2-க்கு மூன்று pages வேணும்: home, about, projects. மற்ற எல்லாமே asset. Pages-ஐ flat-ஆ வெச்சு, assets-க்கு தனி folders வெச்சா படிக்கவும் easy, deploy பண்ணவும் easy.

  • index.html folder-ஓட default file. Hosts அதை automatic-ஆ serve பண்ணும்.
  • மூன்று pages மட்டும் இருக்கும்போது எல்லா pages-ஐயும் ஒரே folder-ல வையுங்கள். Deep folders clarity கூட்டுறதுக்கு முன்னாடி path mistakes-ஐ கூட்டும்.
  • Styles, scripts, images-க்கு தனித்தனி folders வையுங்கள்; அப்போ ஒரு asset-ஐ move பண்ணும்போது pages-ல தேட வேண்டியதில்லை.
Name for the URL

Lowercase file names, hyphens-ஓட use பண்ணுங்கள்: projects.html, project-01.jpg. சில hosts case-sensitive; Projects.html என்பது projects.html-ஐ விட வேற file.

Every page has one job

Shared structure ஒரு site-ஐ ஒரே இடமா feel ஆக வைக்கும். Shared structure-ஆ என்றால் shared content இல்ல. ஒவ்வொரு page-க்கும் ஒரு h1, தெளிவான purpose, "இன்னொரு page" என்பதைத் தாண்டி இருக்க வேணும்-ங்கிற காரணம் தேவை.

PageJobProof it is done
index.htmlநீங்கள் யாரு, என்ன build பண்றீங்க-ங்கிறதை சொல்லும்.தெளிவான h1, சின்ன intro, featured work.
about.htmlவேலைக்கு பின்னாடி இருக்கிற story-யும் skills-ஐயும் சொல்லும்.ஒரு bio, skills list, contact link.
projects.htmlபுரிஞ்சுக்க தேவையான context-ஓட வேலையைக் காட்டும்.குறைந்தது மூன்று project entries, links-ஓட.

shell — skip link, header, navigation, footer — ஒவ்வொரு page-லயும் வரும். நடுப்பகுதி மட்டும் மாறும். Navigation-ஐ edit பண்ணும்போது, மூன்று pages-ஐயும் ஒரே pass-ல edit பண்ணுங்கள். Footer-க்கும் இதே rule.

aria-current="page" என்பது accessible active state. Color-ஐ மட்டும் நம்பாதீர்கள். Visitor இருக்கிற page-ஓட link-க்கு attribute-ஐ move பண்ணுங்கள்; CSS அதை style பண்ணும்.

மேலே இருக்கிற script ஒரு convenience, கட்டாயம் இல்ல. Learn பண்ணும்போது attribute-ஐ hard-code பண்ணினா அது இன்னும் robust, புரிஞ்சுக்கவும் easy. Static version வேலை செய்த பிறகே script-ஐ use பண்ணுங்கள்.

Relative paths are a contract

Relative path அது இருக்கிற file-ல இருந்தே resolve ஆகும். index.html-ல இருந்து projects.html sibling; css/styles.css-ல இருந்து ஒரு image-க்கு ../images/portrait.jpg.

Skip the leading slash

Site domain root-ல இருக்கு-னு தெரியாம internal links-ஐ /-ல தொடங்காதீர்கள். GitHub Pages project sites /repository-name/-ல இருக்கும், அதனால /about.html அங்கே break ஆகும். Paths-ஐ relative-ஆவே வைத்திருங்கள்.

Separate the layers

Inline styles-உம் inline scripts-உம் demo-க்கு பரவாயில்லை, ஆனா மூன்று pages-ல painful. ஒரு stylesheet, ஒரு script மட்டும் வைத்திருங்கள். ஒவ்வொரு page-ல இருந்தும் அந்த page-க்கு relative paths-ஓட அவற்றை link பண்ணுங்கள்.

  • ஒரு stylesheet என்றால் ஒரு color palette, ஒரு spacing scale, mobile bug-ஐ fix பண்ண ஒரே இடம்.
  • defer-ஓட ஒரு script, HTML parse ஆன பிறகு run ஆகும். Page-ல இருக்கிற elements-ஐ safe-ஆ find பண்ணும்.
  • Site ஒரு சில pages-ஐ தாண்டி வளரும்போது, static site generator அல்லது web components-ஐ use பண்ணுங்கள். Header-ஓட மூன்று copies-ஐ தவிர்க்க மட்டும் framework சேர்க்காதீர்கள்.

Plan a three-page site

index.html, about.html, projects.html-க்கான folder tree-ஐ எழுதுங்கள்; அத்துடன் css/styles.css, js/main.js, images/ folder-ஐயும். ஒவ்வொரு page-ல இருந்தும் மற்ற இரண்டு pages-க்கும், இரண்டு assets-க்கும் இருக்கிற relative link-ஐ list பண்ணுங்கள். பிறகு projects.html active-ஆ இருக்கிற navigation markup எழுதுங்கள்.

Check yourself

Why do root-relative links like /about.html break on GitHub Pages?

Project site domain root-ல இருந்து இல்ல, /repository-name/-ல இருந்து serve ஆகுது. /about.html project-க்கு மேல சுட்டுது; about.html current page-ல இருந்து resolve ஆகும்.

How do I avoid copying the header into every page?

Plain static HTML-ல ஒரு file-ஐ directly include பண்ண முடியாது. Markup-ஐ ஒரே மாதிரி வைத்திருங்கள், active link-ஐ மட்டும் மாற்றுங்கள், styling எல்லாம் ஒரே stylesheet-ல வையுங்கள். Site வளரும்போது, தேவையில்லாத framework-க்கு பதிலா static site generator அல்லது component system use பண்ணுங்கள்.

Key things to remember

  • முதலில் map-ஐ plan பண்ணுங்கள். Markup-க்கு முன்னாடி pages, assets, names.
  • Paths file-க்கு relative. ஒவ்வொரு page-ல இருந்தும் ஒவ்வொரு link-ஐயும் test பண்ணுங்கள்.
  • ஒரு shell, ஒரு stylesheet, ஒரு script. Duplication ஒரு maintenance bug.
