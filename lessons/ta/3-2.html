Module 03 · Layout & responsive design

Mobile-first responsive design

ஒரு responsive page மூன்று தனித்தனி layouts அல்ல. சிறியதாகத் தொடங்கி, screen-க்கு இடம் கிடைக்கும்போது columns-ஐயும் scale-ஐயும் சேர்க்கும் ஒரே layout. Mobile-first அந்த logic-ஐ நீங்கள் CSS எழுதும் வரிசையில் வைத்திருக்கிறது.

பாடம் 3.2 60–75 நிமிடங்கள் தொடக்கநிலை

இதன் முடிவில், உங்களால் முடியும்

  • Layout-ஐ சேர்க்கும் min-width media queries எழுதுவது.
  • Breakpoints-ஐ device பெயர்களில் இருந்து அல்ல, content-ல் இருந்து தேர்ந்தெடுப்பது.
  • clamp() மற்றும் responsive images-ஐ பாதுகாப்பாகப் பயன்படுத்துவது.

உங்களுக்குத் தேவை

  • பாடம் 3.1: CSS Grid.
  • Sections மற்றும் குறைந்தது ஒரு image உள்ள page.
  • Widths test செய்ய DevTools device toolbar தேவை.

Viewport-ல் தொடங்குங்கள்

Viewport meta tag இல்லாமல், ஒரு phone தன் screen ஏறக்குறைய 980px அகலம் என்று நினைத்து result-ஐ சுருக்கும். உங்கள் page தூரத்திலிருந்து எடுத்த desktop site photo போலத் தெரியும்; ஒவ்வொரு media query-um தவறான அளவில் trigger ஆகும்.

ஒவ்வொரு page-இன் head-ல் இதை வையுங்கள். முதல் பகுதி layout width-ஐ device width-க்கு சமமாக்குகிறது; இரண்டாவது initial zoom-ஐ சாதாரணமாக அமைக்கிறது. user-scalable=no சேர்க்க வேண்டாம். Zoom ஒரு accessibility feature.

min-width கொண்டு styles-ஐ அடுக்குங்கள்

Mobile-first என்றால் base CSS குறுகிய layout-ஐ விவரிக்கிறது. இடம் இருக்கும்போது மட்டும் media queries கூடுதல் சிக்கல்களைச் சேர்க்கின்றன. இரண்டு rules-க்கும் ஒரே specificity இருப்பதால், condition true ஆகும்போது பிறகு வரும் min-width block வெற்றி பெறும்.

max-width பயன்படுத்தும் desktop-first rule-உடன் இதை ஒப்பிடுங்கள். Base styles அகலமான screen-ஐ எடுத்துக்கொண்டு, screen சுருங்கும்போது columns-ஐ நீக்குகின்றன. இதுவும் வேலை செய்யும், ஆனால் குறுகிய நிலைக்கான முடிவுகளை வரையறுப்பதற்குப் பதிலாக அவற்றை override செய்வதில் நேரம் செலவாகும்.

அகலம்என்ன சரிபார்க்க வேண்டும்
320pxபக்கவாட்டு scroll இல்லை, body text படிக்கக்கூடியதாக இருக்க வேண்டும், tap targets குறைந்தது 44px உயரம், heading overflow ஆகக்கூடாது.
768pxஇரண்டு column sections align ஆக வேண்டும், images stretch ஆகக்கூடாது, navigation இன்னும் பொருந்த வேண்டும்.
1440pxLine lengths 65ch அருகில் இருக்க வேண்டும், content edges-ஐ ஒட்டக்கூடாது, மிகப்பெரிய காலி இடங்கள் இருக்கக்கூடாது.

Breakpoints content-ஐப் பின்பற்றுகின்றன

Phones, tablets என்று பெயர் சொல்லி breakpoints தேர்ந்தெடுக்க வேண்டாம். Browser-ஐ மெதுவாக resize செய்து, layout வேலை செய்யாமல் போகும் இடத்தில் breakpoint சேர்க்கவும்: text வரி மிக நீளமாகிறது, cards மிகக் குறுகுகின்றன, அல்லது navigation மோசமாக wrap ஆகிறது.

  • பிரச்சினை தோன்றுவதற்கு சற்று முந்தைய அகலத்தில் breakpoint எழுதுங்கள்.
  • em-அடிப்படையிலான queries பயனரின் font settings-க்கு ஏற்ப scale ஆகும்: 768px-ஐ விட 48em பொதுவாக சிறந்த தேர்வு.
  • பெரும்பாலான projects-க்கு இரண்டு அல்லது மூன்று breakpoints போதும்; ஒவ்வொரு device-க்கும் ஒன்று தேவையில்லை.
  • சரியான மதிப்புகளை மட்டுமல்ல, breakpoints-க்கு இடையிலான இடைவெளியையும் test செய்யுங்கள்.

Fluid type தேவையான queries எண்ணிக்கையைக் குறைக்கிறது. clamp(minimum, preferred, maximum) ஒரு மதிப்பு viewport-உடன் வளர அனுமதிக்கிறது; ஆனால் நீங்கள் அமைத்த எல்லைகளுக்கு வெளியே போகாது.

நடுவில் உள்ள மதிப்பு fluid வேலையைச் செய்கிறது; வெளிப்புற மதிப்புகள் result படிக்கக்கூடியதாக வைத்திருக்கின்றன. Headings மற்றும் பெரிய spacing-க்கு clamp() பயன்படுத்துங்கள்; ஒவ்வொரு மதிப்புக்கும் வேண்டாம். Body text 1rem அருகில் இருக்க வேண்டும்.

Images மற்றும் horizontal overflow

தன் container-ஐ விட அகலமான image தான் பக்கவாட்டு scrolling-க்கு மிகப் பொதுவான காரணம். Images இயல்பாகவே சரியாக நடந்துகொள்ளச் செய்யுங்கள்.

  • max-width: 100% மற்றும் height: auto column-க்குள் பொருந்தும் அதே நேரத்தில் aspect ratio-ஐ வைத்திருக்கும்.
  • srcset மற்றும் sizes browser தான் ஆக்கிரமிக்கப்போகும் இடத்திற்கு ஏற்ற file-ஐ download செய்ய அனுமதிக்கின்றன.
  • இடத்தை ஒதுக்கி layout shift-ஐ குறைக்க எப்போதும் width மற்றும் height attributes வைத்திருங்கள்.
  • நிலையான aspect ratio முக்கியமானபோது object-fit: cover பயன்படுத்துங்கள்; image நசுங்காமல் crop ஆகும்.
பிரச்சினையை மறைக்க வேண்டாம்

body-ல் overflow-x: hidden போட்டால் பக்கவாட்டு scrolling மறையும்; ஆனால் அதற்குக் காரணமானதை சரிசெய்யாமல் விடுவீர்கள். DevTools-ல் அகலமான element-ஐ கண்டுபிடித்து அதன் sizing-ஐ சரிசெய்யுங்கள். திட்டமிட்ட decorative bleed-க்கு மட்டும் overflow clipping-ஐ வைத்திருக்கவும்.

இரண்டு column section-ஐ stack செய்யுங்கள்

இரண்டு children உள்ள .split section-க்கு mobile-first CSS எழுதுங்கள். 700px-க்குக் கீழே children 1.5rem gap-உடன் ஒரே column-ல் stack ஆக வேண்டும். 700px மற்றும் அதற்கு மேல் 2.5rem gap-உடன் இரண்டு சமமான columns-ல் அமைய வேண்டும். நீளமான content page-ஐ அகலமாக்காமல் இருக்க minmax(0, 1fr) பயன்படுத்துங்கள்.

முதலில் ஒரு முயற்சி செய்யுங்கள். பிறகு மாதிரி விடை திறக்கும்.

உங்களைச் சரிபாருங்கள்

max-width-ஐ விட min-width query பொதுவாக ஏன் சிறந்தது?

சிறிய screen layout-ஐ default ஆக வைத்து, இடம் இருக்கும்போது மட்டும் rules சேர்க்க அனுமதிக்கிறது. இது CSS-ஐ சுருக்கமாக வைத்து, குறுகிய screen ஒரு desktop assumption-ஐ பெறுவதற்கான வாய்ப்பைக் குறைக்கிறது.

clamp() media queries-ன் தேவையை நீக்கிவிடுமா?

இல்லை. இது மதிப்புகளை மென்மையாக scale செய்கிறது; ஆனால் grid-ஐ மறுசீரமைக்க, navigation-ஐ மாற்ற, அல்லது content-ஐ reorder செய்ய முடியாது. அளவுக்கு clamp(), structure-க்கு media queries பயன்படுத்துங்கள்.

நினைவில் வைக்க வேண்டிய முக்கிய விஷயங்கள்

  • Viewport முதலில். Meta tag இல்லாமல், ஒவ்வொரு responsive முடிவும் தவறான அகலத்திற்கு எதிராக அளவிடப்படும்.
  • சிறிய screens தான் default. Columns மற்றும் spacing சேர்க்க min-width பயன்படுத்துங்கள்.
  • Device பெயர்களை அல்ல, content-ஐ test செய்யுங்கள். 320, 768, 1440 ஆகியவற்றைச் சரிபார்த்து, overflow-ஐ மறைப்பதற்குப் பதிலாக அதன் காரணத்தைச் சரிசெய்யுங்கள்.
