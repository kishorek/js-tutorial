Module 03 · Layout & responsive design

Mobile-first responsive design

Responsive page மூன்று தனி layouts இல்ல. சிறியதா start ஆகி, screen-க்கு space கிடைக்கும்போது columns-ஐயும் scale-ஐயும் சேர்த்துக்கும் ஒரே layout. Mobile-first அந்த logic-ஐ நீங்கள் CSS எழுதும் order-லயே வைத்திருக்கும்.

Start with the viewport

Viewport meta tag இல்லாம, phone தன் screen சுமார் 980px அகலம்-னு நினைச்சு result-ஐ shrink பண்ணும். Page தூரத்துல இருந்து எடுத்த desktop site photo மாதிரி தெரியும்; ஒவ்வொரு media query-உம் தப்பான size-ல trigger ஆகும்.

ஒவ்வொரு page-இன் head-லயும் இதை வையுங்கள். முதல் part layout width-ஐ device width-க்கு சமமாக்கும்; இரண்டாவது initial zoom-ஐ normal-ஆ set பண்ணும். user-scalable=no add பண்ணாதீங்க. Zoom ஒரு accessibility feature.

Layer styles with min-width

Mobile-first-னா base CSS சிறிய layout-ஐ describe பண்ணும். Space இருக்கும்போது மட்டும் media queries complexity-ஐ add பண்ணும். இரண்டு rules-க்கும் ஒரே specificity இருக்குறதால, condition true ஆனப்போ, கடைசியா வரும் min-width block win பண்ணும்.

max-width use பண்ணும் desktop-first rule-உடன் இதை compare பண்ணுங்கள். Base styles அகலமான screen-ஐ assume பண்ணி, screen shrink ஆனப்போ columns-ஐ undo பண்ணும். இதுவும் work ஆகும், ஆனா சிறிய case-க்கான decisions-ஐ define பண்றதுக்கு பதிலா override பண்றதுல நேரம் போகும்.

Breakpoints follow the content

Phones, tablets-னு பேர் சொல்லி breakpoints choose பண்ணாதீங்க. Browser-ஐ மெதுவா resize பண்ணி, layout வேலை செய்யாத இடத்துல breakpoint add பண்ணுங்கள்: text line ரொம்ப நீளமாகுது, cards ரொம்ப குறுகுது, இல்ல navigation மோசமா wrap ஆகுது.

  • பிரச்சினை வருவதுக்கு சற்று முன்னாடி இருக்குற width-ல breakpoint எழுதுங்கள்.
  • em-based queries user-ஓட font settings-க்கு ஏத்தபடி scale ஆகும்: 768px-ஐ விட 48em பொதுவா நல்ல choice.
  • பெரும்பாலான projects-க்கு இரண்டு அல்லது மூன்று breakpoints போதும்; ஒவ்வொரு device-க்கும் ஒண்ணு வேண்டாம்.
  • Exact values மட்டும் இல்லாம, breakpoints-க்கு நடுவிலான gap-ஐயும் test பண்ணுங்கள்.

Fluid type தேவைப்படும் queries எண்ணிக்கையை குறைக்கும். clamp(minimum, preferred, maximum) ஒரு value viewport-உடன் grow ஆக விடும்; ஆனா நீங்கள் set பண்ண எல்லைக்கு வெளியே போகாது.

நடுவில இருக்குற value தான் fluid வேலையை பண்ணும்; வெளியில இருக்குற values result-ஐ readable-ஆ வைத்திருக்கும். Headings-க்கும் பெரிய spacing-க்கும் clamp() use பண்ணுங்கள்; எல்லா value-க்கும் வேண்டாம். Body text 1rem அருகிலேயே இருக்கணும்.

Images and horizontal overflow

தன் container-ஐ விட அகலமான image தான் பக்கவாட்டு scrolling-க்கு மிக பொதுவான காரணம். Images default-ஆவே சரியா behave பண்ண வையுங்கள்.

  • max-width: 100% மற்றும் height: auto column-க்குள்ள fit ஆகும்போதே aspect ratio-ஐ வைத்திருக்கும்.
  • srcset மற்றும் sizes browser தான் எடுத்துக்கப்போற space-க்கு ஏத்த file-ஐ download பண்ண விடும்.
  • Space reserve பண்ணி layout shift-ஐ குறைக்க எப்போதும் width மற்றும் height attributes வைத்திருங்கள்.
  • Fixed aspect ratio முக்கியமானப்போ object-fit: cover use பண்ணுங்கள்; image squash ஆகாம crop ஆகும்.
Do not hide the problem

body-ல overflow-x: hidden போட்டா பக்கவாட்டு scrolling மறையும்; ஆனா அதுக்கு காரணத்தை fix பண்ணாம விட்டுடுவீங்க. DevTools-ல அகலமான element-ஐ கண்டுபிடிச்சு அதன் sizing-ஐ சரிசெய்யுங்கள். வேண்டும்னு பண்ணும் decorative bleed-க்கு மட்டும் overflow clipping-ஐ வைத்திருங்கள்.

Check yourself

Why is a min-width query usually better than max-width?

சிறிய screen layout-ஐ default-ஆ வைத்து, space இருக்கும்போது மட்டும் rules add பண்ண விடும். அதனால CSS சுருக்கமா இருக்கும்; சிறிய screen ஒரு desktop assumption-ஐ inherit பண்ற chance-ஐ குறைக்கும்.

Does clamp() remove the need for media queries?

இல்ல. Values-ஐ smooth-ஆ scale பண்ணும்; ஆனா grid-ஐ rearrange பண்ண, navigation-ஐ மாற்ற, அல்லது content-ஐ reorder பண்ண முடியாது. Size-க்கு clamp(), structure-க்கு media queries use பண்ணுங்கள்.

Key things to remember

  • Viewport first. Meta tag இல்லாம, ஒவ்வொரு responsive decision-உம் தப்பான width-க்கு எதிரா measure ஆகும்.
  • Small screens are the default. Columns-ஐயும் spacing-ஐயும் add பண்ண min-width use பண்ணுங்கள்.
  • Test content, not device names. 320, 768, 1440-ஐ check பண்ணி, overflow-ஐ மறைக்காம அதன் காரணத்தை fix பண்ணுங்கள்.
