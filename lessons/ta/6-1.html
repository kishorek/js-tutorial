Promises and async/await

JavaScript மெதுவான வேலைக்காக wait பண்ணாது. பின்னாடி முடியும் வேலையை promises எப்படி represent பண்ணுது, async மற்றும் await அந்த flow-ஐ சாதாரண code மாதிரி எப்படிப் படிக்க வைக்குது — அதைப் பாருங்க.

JavaScript does not wait

Synchronous code ஒரு நேரத்துல ஒரு line ஆக, order-ல run ஆகும். அடுத்த line start ஆகுறதுக்கு முன்னாடி ஒவ்வொரு line-ம் முடிஞ்சிரும். இதைப் புரிஞ்சுக்க easy, ஆனா slow operation அதுக்குப் பின்னாடி இருக்குற எல்லாத்தையும் freeze பண்ணிடும்.

Asynchronous code ஒரு task-ஐ start பண்ணி, அடுத்த வேலைக்குப் போய், result-ஐ பின்னாடி handle பண்ணும். Timers, network requests, file reads எல்லாம் asynchronous. Delay zero milliseconds ஆனாலும், current வேலை முடிஞ்ச பிறகுதான் callback run ஆகும்.

பல வருஷமா இதை handle பண்ண main வழி callbacks-தான். அவை work ஆகும், ஆனா நிறைய callbacks-ஐ உள்ளுக்கு உள்ளே வச்சா படிக்க கஷ்டமான, debug பண்ண இன்னும் கஷ்டமான pyramid உருவாகும். அந்த shape-ஐ flat பண்ணத்தான் promises introduce பண்ணாங்க.

One mental model

Promise-னா இன்னும் ready ஆகாத ஒரு value-க்கான receipt. இப்பவே handlers attach பண்ணலாம்; value வந்ததும் அவை run ஆகும்.

Promises have three states

வேலை run ஆகிக்கொண்டிருக்கும்போது promise pending-ல இருக்கும். அது ஒரு value-ஓட fulfilled ஆகலாம், இல்ல error-ஓட rejected ஆகலாம். ஒரு தடவை settle ஆனா, அது மறுபடி மாற முடியாது.

Promise constructor-ஐ use பண்ணி ஒண்ணு create பண்ணுங்கள். Result-ஓட resolve-ஐ call பண்ணுங்கள்; இல்ல Error-ஓட reject-ஐ call பண்ணுங்கள்.

Fulfilled value-ஐ handle பண்ண .then(), rejection-ஐ handle பண்ண .catch(), எப்படியும் run ஆக வேண்டிய cleanup-க்கு .finally() use பண்ணுங்கள்.

ஒவ்வொரு .then()-ம் புது promise-ஐ return பண்ணும். Handler-லேர்ந்து promise-ஐ return பண்ணா, அடுத்த .then() அதுக்காக wait பண்ணும். அதுதான் chain-ஐ nested ஆகாம flat-ஆ வச்சிருக்கும்.

Do not forget to return

.then() handler ஒரு promise-ஐ start பண்ணி அதை return பண்ணலனா, அடுத்த step ரொம்ப சீக்கிரம் run ஆகும். Chain சரியா தெரியும், ஆனா சத்தமில்லாம தப்பான order-ஐ கொடுக்கும்.

async and await

async function எப்பவும் ஒரு promise-ஐ return பண்ணும். அதுக்குள்ள await அந்த function-ஐ promise settle ஆகுற வரைக்கும் pause பண்ணும், page-ன் மற்ற பகுதிகளை block பண்ணாம. Code மறுபடி மேலிருந்து கீழ படிக்கப்படும்.

இது மேல இருக்குற chain மாதிரியே same logic. try block success-ஐ handle பண்ணும், catch rejected promise-ஐ handle பண்ணும், finally அதுக்குப் பிறகு run ஆகும். await async function-க்குள்ள அல்லது module-ன் top level-ல மட்டுமே work ஆகும்.

காரணமில்லாம ரெண்டு style-ஐயும் mix பண்ணாதீங்க. நிறைய code-க்கு async/await-ஐ pick பண்ணுங்கள்; ஏற்கனவே promise chain-ஓட work பண்றீங்க இல்ல சின்ன inline handler வேணும்னா .then() use பண்ணுங்கள்.

Wait together, not one by one

ரெண்டு independent requests-ஐ order-ஆ run பண்ண வேண்டியதில்ல. Promise.all() அவற்றை ஒண்ணா start பண்ணி, எல்லா promises-ம் fulfill ஆனதும் resolve ஆகும். ஏதாவது ஒண்ணு reject ஆனா, combined promise-ம் reject ஆகும்.

எல்லா result-ம் வேணும்னா Promise.all() use பண்ணுங்கள். ஒரு failure மற்றதை cancel பண்ணக்கூடாதுன்னா, Promise.allSettled() use பண்ணி ஒவ்வொரு result-ஐயும் check பண்ணுங்கள்.

Rewrite the chain with async/await

கீழ இருக்குற chain ஒரு profile-ஐ load பண்ணி, பிறகு அதோட posts-ஐ load பண்ணும். இதை showProfile-னு ஒரு async function-ஆ rewrite பண்ணுங்கள். ரெண்டு calls-க்கும் await use பண்ணுங்கள், வேலையை try/catch-ல wrap பண்ணி, post count-ஐ log பண்ணுங்கள். "finished"-ஐ log பண்ண ஒரு finally-ம் add பண்ணுங்கள்.

Check yourself

What is the difference between pending and fulfilled?

Pending-னா வேலை இன்னும் run ஆகிக்கொண்டிருக்கு, promise-க்கு இன்னும் final value இல்ல. Fulfilled-னா வேலை success-ஆ முடிஞ்சு இப்போ ஒரு value வச்சிருக்கு. ஒரு promise ஒரு தடவை மட்டுமே settle ஆக முடியும்.

Why does await not freeze the rest of the page?

await அதை வைச்சிருக்குற async function-ஐ மட்டும்தான் pause பண்ணும். Browser-ன் main thread release ஆகுது, அதனால promise pending-ஆ இருக்கும்போது மற்ற events, rendering, user input தொடரலாம்.

Key things to remember

  • Async வேலை பின்னாடி முடியும். Promise-னா வந்து சேரலாம் இல்ல fail ஆகலாம் — அந்த value-க்கான placeholder.
  • .then()-லேர்ந்து promises-ஐ return பண்ணுங்கள். அது chain-ஐ order-ல வைக்கும்; return-ஐ மறந்தா பிறகு வர steps ரொம்ப சீக்கிரம் run ஆகும்.
  • async/await-தான் படிக்க easy default. Failure-க்கு try/catch, independent வேலைக்கு Promise.all use பண்ணுங்கள்.
