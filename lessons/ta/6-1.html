Promises மற்றும் async/await

JavaScript மெதுவான வேலைக்காகக் காத்திருக்காது. பின்னர் முடியும் வேலையை promises எப்படிக் குறிக்கின்றன, async மற்றும் await அந்த flow-ஐ சாதாரண code போல எப்படிப் படிக்க வைக்கின்றன என்பதைக் கற்றுக்கொள்ளுங்கள்.

பாடம் 6.1 60–75 நிமிடம் தொடக்கநிலை

இந்தப் பாடம் முடியும்போது, நீங்கள்:

  • Synchronous மற்றும் asynchronous வேலைக்கு இடையிலான வேறுபாட்டை விளக்குங்கள்.
  • சிறிய promise chain-ஐ படித்து எழுதுங்கள்.
  • ஒரு chain-ஐ try/catch உடன் async/await ஆக மாற்றுங்கள்.
  • சுயாதீன promises-ஐ Promise.all மூலம் ஒன்றாக இயக்குங்கள்.

உங்களுக்குத் தேவை

  • பாடம் 5.3-ல் உள்ள state மற்றும் rendering.
  • ஒரு browser console திறந்திருக்க வேண்டும்.
  • பின்னர் முடியும் code-க்காகப் பொறுமை.

JavaScript காத்திருக்காது

Synchronous code ஒரு நேரத்தில் ஒரு வரியாக, வரிசையாக இயங்கும். அடுத்த வரி தொடங்குவதற்கு முன் ஒவ்வொரு வரியும் முடிந்துவிடும். இதைப் புரிந்துகொள்வது எளிது, ஆனால் மெதுவான operation அதற்குப் பின்னால் உள்ள எல்லாவற்றையும் freeze செய்துவிடும்.

Asynchronous code ஒரு வேலையைத் தொடங்கி, அடுத்த வேலைக்குச் சென்று, முடிவைப் பின்னர் கையாளும். Timers, network requests, file reads ஆகியவை asynchronous. Delay பூஜ்ஜிய milliseconds ஆனாலும், தற்போதைய வேலை முடிந்த பிறகே callback இயங்கும்.

பல ஆண்டுகளாக இதைக் கையாள முக்கிய வழி callbacks ஆக இருந்தது. அவை வேலை செய்கின்றன, ஆனால் பல callbacks-ஐ உள்ளுக்குள் வைப்பது படிக்கக் கடினமான, debug செய்ய இன்னும் கடினமான pyramid-ஐ உருவாக்குகிறது. அந்த வடிவத்தைத் தட்டையாக்கவே promises அறிமுகப்படுத்தப்பட்டன.

ஒரு mental model

Promise என்பது இன்னும் தயாராகாத ஒரு value-க்கான ரசீது. இப்போதே handlers இணைக்கலாம்; value வந்தவுடன் அவை இயங்கும்.

Promises-க்கு மூன்று நிலைகள் உண்டு

வேலை நடந்துகொண்டிருக்கும்போது promise pending நிலையில் இருக்கும். அது ஒரு value உடன் fulfilled ஆகலாம், அல்லது error உடன் rejected ஆகலாம். ஒருமுறை settle ஆனதும், அது மீண்டும் மாற முடியாது.

Promise constructor மூலம் ஒன்றை உருவாக்குங்கள். முடிவுடன் resolve-ஐ அழையுங்கள்; அல்லது Error உடன் reject-ஐ அழையுங்கள்.

Fulfilled value-ஐ கையாள .then(), rejection-ஐ கையாள .catch(), எப்படியும் இயங்க வேண்டிய cleanup-க்கு .finally() பயன்படுத்துங்கள்.

ஒவ்வொரு .then() புதிய promise-ஐத் திருப்பித் தரும். Handler-ல் இருந்து promise-ஐ return செய்தால், அடுத்த .then() அதற்காகக் காத்திருக்கும். அதுதான் chain-ஐ nested ஆகாமல் தட்டையாக வைத்திருக்கிறது.

Return செய்ய மறக்காதீர்கள்

.then() handler ஒரு promise-ஐத் தொடங்கி அதை return செய்யாவிட்டால், அடுத்த step மிக விரைவாக இயங்கும். Chain சரியாகத் தெரியும், ஆனால் அமைதியாகத் தவறான வரிசையை உருவாக்கும்.

async மற்றும் await

async function எப்போதும் ஒரு promise-ஐத் திருப்பித் தரும். அதற்குள், promise settle ஆகும் வரை await அந்த function-ஐ இடைநிறுத்தும்; பக்கத்தின் மற்ற பகுதிகளை block செய்யாது. Code மீண்டும் மேலிருந்து கீழாகப் படிக்கப்படும்.

இது மேலே உள்ள chain-ஐப் போன்ற அதே logic. try block வெற்றியைக் கையாளும், catch rejected promise-ஐக் கையாளும், finally அதன் பிறகு இயங்கும். await async function-க்குள் அல்லது module-ன் top level-ல் மட்டுமே வேலை செய்யும்.

காரணமில்லாமல் இரு style-களையும் கலக்க வேண்டாம். பெரும்பாலான code-க்கு async/await-ஐத் தேர்ந்தெடுங்கள்; ஏற்கனவே promise chain-ல் வேலை செய்கிறீர்கள் அல்லது சிறிய inline handler தேவைப்பட்டால் .then() பயன்படுத்துங்கள்.

ஒன்றாகக் காத்திருங்கள், ஒவ்வொன்றாக அல்ல

இரண்டு சுயாதீன requests வரிசையாக இயங்கத் தேவையில்லை. Promise.all() அவற்றை ஒன்றாகத் தொடங்கி, எல்லா promises-ம் fulfill ஆனதும் resolve ஆகும். ஏதேனும் ஒன்று reject ஆனால், ஒருங்கிணைந்த promise-ம் reject ஆகும்.

எல்லா முடிவுகளும் தேவைப்படும்போது Promise.all() பயன்படுத்துங்கள். ஒரு தோல்வி மற்றவற்றை ரத்து செய்யக்கூடாது என்றால், Promise.allSettled() பயன்படுத்தி ஒவ்வொரு முடிவையும் சரிபாருங்கள்.

Chain-ஐ async/await கொண்டு மீண்டும் எழுதுங்கள்

கீழே உள்ள chain ஒரு profile-ஐயும், பிறகு அதன் posts-ஐயும் load செய்கிறது. இதை showProfile என்ற async function ஆக மீண்டும் எழுதுங்கள். இரண்டு calls-க்கும் await பயன்படுத்துங்கள், வேலையை try/catch-ல் வைத்து, post எண்ணிக்கையை log செய்யுங்கள். "finished" என்று log செய்யும் finally-ஐச் சேர்க்கவும்.

முதலில் ஒரு முயற்சி செய்யுங்கள். பிறகு மாதிரி விடை திறக்கும்.

உங்களைச் சரிபாருங்கள்

pending மற்றும் fulfilled இடையிலான வேறுபாடு என்ன?

Pending என்றால் வேலை இன்னும் நடந்துகொண்டிருக்கிறது, promise-க்கு இன்னும் இறுதி value இல்லை. Fulfilled என்றால் வேலை வெற்றிகரமாக முடிந்து இப்போது ஒரு value வைத்திருக்கிறது. ஒரு promise ஒருமுறை மட்டுமே settle ஆக முடியும்.

await பக்கத்தின் மற்ற பகுதிகளை ஏன் freeze செய்யாது?

await அதைக் கொண்டுள்ள async function-ஐ மட்டுமே இடைநிறுத்தும். Browser-ன் main thread விடுவிக்கப்படுவதால், promise pending-ஆக இருக்கும்போது மற்ற events, rendering, user input தொடரலாம்.

நினைவில் கொள்ள வேண்டிய முக்கிய விஷயங்கள்

  • Async வேலை பின்னர் முடியும். Promise என்பது வந்து சேரக்கூடிய அல்லது தோல்வியடையக்கூடிய ஒரு value-க்கான placeholder.
  • .then()-ல் இருந்து promises-ஐ return செய்யுங்கள். அது chain-ஐ வரிசையாக வைத்திருக்கும்; return-ஐ மறந்தால் பிந்தைய steps மிக விரைவாக இயங்கும்.
  • async/await தான் படிக்க எளிதான default. தோல்விக்கு try/catch, சுயாதீன வேலைக்கு Promise.all பயன்படுத்துங்கள்.
