அணுகல்தன்மை மற்றும் செயல்திறன் தணிக்கை

Mouse மற்றும் வேகமான இணைப்பு இருந்தால் மட்டுமே வேலை செய்யும் தளம் மக்களை இழக்கும் தளம். ஒவ்வொரு முறையும் அதே தணிக்கையைச் செய்யுங்கள்: keyboard, focus, contrast, labels, images, motion, மற்றும் பார்வையாளர்கள் download செய்ய நீங்கள் கேட்கும் bytes.

  • தவிர்க்கக்கூடிய layout shift-ஐயும் download எடையையும் குறைக்க முடியும்.

அணுகல்தன்மை ஒரு அடிப்படை

WCAG என்பது Web Content Accessibility Guidelines. முழுமையை அல்ல, AA நிலையை இலக்காகக் கொள்ளுங்கள். நான்கு கொள்கைகளை POUR என்று நினைவில் வைப்பது எளிது: உள்ளடக்கம் perceivable, operable, understandable, robust ஆக இருக்க வேண்டும். அன்றாட code-ல் இது ஆறு பழக்கங்களைக் குறிக்கும்.

  • Keyboard முதலில். ஒவ்வொரு இணைப்பு, button, field, menu-வும் Tab, Shift+Tab, Enter, Space, மற்றும் எதிர்பார்க்கும் இடங்களில் arrow keys-உடன் வேலை செய்ய வேண்டும்.
  • தெளிவாகத் தெரியும் focus. focus outline-ஐ மாற்றீடு இல்லாமல் ஒருபோதும் நீக்காதீர்கள். தெளிவான ring, keyboard பயனர்கள் எங்கே இருக்கிறார்கள் என்பதைக் காட்டும்.
  • Contrast. உடல் உரை அதன் பின்னணிக்கு எதிராக குறைந்தது 4.5:1 தேவை. பெரிய உரை மற்றும் interface எல்லைகளுக்கு குறைந்தது 3:1 தேவை.
  • பெயர்கள். ஒவ்வொரு input-க்கும் உண்மையான label இருக்க வேண்டும். அர்த்தமுள்ள ஒவ்வொரு படத்திற்கும் பயனுள்ள alt உரை இருக்க வேண்டும். அலங்காரப் படங்கள் alt="" பயன்படுத்தும்.
  • அமைப்பு. ஒரு main, தர்க்கமான heading வரிசை, header, nav, footer போன்ற landmarks பயன்படுத்துங்கள். ஒரு skip link சேர்க்கவும்.
  • Motion. prefers-reduced-motion-ஐ மதியுங்கள்; எதையும் புரிந்துகொள்ள animation மட்டுமே வழியாக இருக்கக் கூடாது.
Overlay-கள் தீர்வு அல்ல

Accessibility widget, button போல் நடிக்கும் div, label இல்லாத input, படிக்க முடியாத contrast ஆகியவற்றைச் சரிசெய்ய முடியாது. HTML, CSS-ஐ அடிப்படையிலேயே சரிசெய்யுங்கள்.

ஒவ்வொரு முறையும் அதே தணிக்கையைச் செய்யுங்கள்

இந்த checklist-ஐ print செய்யுங்கள் அல்லது editor-க்கு அருகில் வைத்திருங்கள். சிறிய தளத்தில் முழு pass-க்கு சுமார் பதினைந்து நிமிடங்கள் ஆகும்.

பகுதிசரிபார்ப்புவெற்றி எப்படி இருக்கும்
Keyboardமுழுப் பக்கத்திலும் Tab அழுத்துங்கள்.ஒவ்வொரு control-உம் அடையக்கூடியதாக, சரியான வரிசையில், trap இல்லாமல் இருக்கும்.
Focusஒவ்வொரு control-இலும் focus ring-ஐப் பாருங்கள்.பின்னணிக்கு எதிராகத் தெளிவாகத் தெரியும்.
StructureHeading outline-ஐயும் landmarks-ஐயும் படியுங்கள்.ஒரு h1, தவிர்க்கப்பட்ட நிலைகள் இல்லை, ஒரு main.
Text200% வரை zoom செய்து contrast-ஐச் சரிபாருங்கள்.உரை வெட்டப்படவில்லை; body உரை 4.5:1-ஐ பூர்த்தி செய்கிறது.
Imagesஒவ்வொரு img-ஐயும் பாருங்கள்.பயனுள்ள alt, மேலும் width, height.
Formsஒவ்வொரு label-ஐயும் click செய்து காலியாக submit செய்யுங்கள்.Labels தங்கள் field-ஐ focus செய்யும்; பிழைகள் அறிவிக்கப்பட்டு தெளிவாக இருக்கும்.
MotionOS-ல் reduced motion-ஐ இயக்குங்கள்.அத்தியாவசியமான எதுவும் animation-ஐச் சார்ந்திருக்காது.
Assetsபடங்களின் எடை, fonts, CSS, JS-ஐச் சரிபாருங்கள்.படங்களுக்கு அளவு உள்ளது; fonts swap ஆகும்; scripts defer ஆகியுள்ளன.

கண்ணுக்குத் தெரியும் தோல்விகளைச் சரிசெய்யுங்கள்

இந்த card ஒரு பொதுவான முதல் draft. Click செய்யலாம் போல் தெரியும், ஆனால் keyboard-ல் பயன்படுத்த முடியாது, படத்திற்கு மாற்று உரை இல்லை, குறைந்த contrast உரை பல வாசகர்களுக்கு மறைந்துவிடும்.

மீண்டும் எழுதப்பட்ட பதிப்பு உண்மையான article, உண்மையான இணைப்பு, பயனுள்ள மாற்று உரை, ஒதுக்கப்பட்ட பட இடம், fold-க்குக் கீழே உள்ள படத்திற்கு lazy loading, படிக்கக்கூடிய contrast ஆகியவற்றைப் பயன்படுத்துகிறது.

Focus, motion-க்கும் CSS தேவை. outline-ஐ வலுவாக வைத்திருங்கள்; பார்வையாளர் கேட்கும்போது motion-ஐ குறைக்கவும்.

Checklist அல்ல, keyboard-உடன் சோதியுங்கள்

Mouse-ஐ ஒதுக்கி வைத்து முக்கிய வேலையை முடியுங்கள். focus எங்கே போனது என்று உங்களுக்குத் தெரியாவிட்டால், keyboard பயனருக்கும் தெரியாது. பிறகு ஐந்து நிமிடம் screen reader-ஐ முயற்சியுங்கள்; VoiceOver, NVDA, TalkBack இலவசம்.

செயல்திறன் அனுபவத்தின் ஒரு பகுதி

மெதுவான சாதனங்கள், நம்பமுடியாத network-களுக்கு performance என்பது அணுகல்தன்மை. மிகப் பெரிய தெரியும் படம், fonts, JavaScript ஆகியவற்றிலிருந்து தொடங்குங்கள்.

  • பட இடத்தை ஒதுக்குங்கள். கோப்பு வரும்போது layout துள்ளாமல் இருக்க width, height அமைக்கவும்.
  • Fold-க்குக் கீழே lazy-load செய்யுங்கள். கீழே உள்ள படங்களுக்கு loading="lazy" பயன்படுத்துங்கள். Hero படத்தை lazy-load செய்யாதீர்கள்; அது largest contentful paint-ஐ பாதிக்கும்.
  • Fonts swap ஆகட்டும். font-display: swap பயன்படுத்துங்கள், நீங்கள் பயன்படுத்தும் weights மட்டும் load செய்யுங்கள், ஒரே family-ஐ விரும்புங்கள்.
  • குறைவான JavaScript அனுப்புங்கள். பயன்படுத்தாத library-களை நீக்குங்கள், scripts-ஐ defer செய்யுங்கள், தேவையை விட பெரிய கோப்புகளுக்கு Network panel-ஐப் பாருங்கள்.
  • Mobile-ல் அளவிடுங்கள். Mobile setting, throttled connection-உடன் Lighthouse இயக்குங்கள். Desktop score என்பது உங்கள் பார்வையாளர்கள் பெறும் score அல்ல.
Score-கள் ஒரு smoke alarm

Lighthouse-ல் சரியான score வந்தால் பக்கம் அணுகக்கூடியது என்று நிரூபணமாகாது. தானியங்கிக் கருவிகள் பிரச்சினையின் ஒரு பகுதியை மட்டுமே பிடிக்கும்; keyboard சோதனையும் மனித மதிப்பீடும் மீதியைப் பிடிக்கும்.

Promo block-ஐ தணிக்கை செய்து சரிசெய்யுங்கள்

இந்த snippet-ல் குறைந்தது ஐந்து அணுகல்தன்மைப் பிரச்சினைகளைக் கண்டறிந்து, பிறகு மீண்டும் எழுதுங்கள். Heading உள்ள section, உண்மையான இணைப்பு அல்லது button, label உள்ள email field, பயனுள்ள alt உரை, படத்தின் அளவுகள், படிக்கக்கூடிய contrast பயன்படுத்துங்கள். படம் fold-க்குக் கீழே உள்ளது என்று வைத்துக்கொள்ளுங்கள்.

உங்களைச் சோதித்துக் கொள்ளுங்கள்

Lighthouse score 100 என்றால் பக்கம் அணுகக்கூடியது என்று அர்த்தமா?

இல்லை. தானியங்கிச் சோதனைகள் சில இல்லாத பெயர்கள், contrast தோல்விகள், அமைப்புப் பிரச்சினைகளைப் பிடிக்கும்; ஆனால் keyboard வரிசை அர்த்தமுள்ளதா, screen-reader அனுபவம் தெளிவாக உள்ளதா என்பதை அவை மதிப்பிட முடியாது. உண்மையான interaction-ஐச் சோதியுங்கள்.

ஒவ்வொரு படத்திற்கும் loading="lazy" சேர்க்கக் கூடாது ஏன்?

Lazy loading, browser தேவை என்று நினைக்கும் வரை படத்தைத் தாமதப்படுத்தும். Hero அல்லது fold-க்கு மேலே உள்ள மிகப்பெரிய படத்தில் அது பக்கத்தை மெதுவாக உணர வைக்கும். Fold-க்குக் கீழே உள்ள படங்களுக்கு இதைப் பயன்படுத்துங்கள்.
