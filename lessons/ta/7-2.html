Accessibility and performance audit

Mouse-உம் fast connection-உம் இருந்தா மட்டும் வேலை செய்யிற site மக்களை இழக்கிற site. ஒவ்வொரு முறையும் அதே audit-ஐ run பண்ணுங்கள்: keyboard, focus, contrast, labels, images, motion, மற்றும் visitors download பண்ண நீங்கள் கேக்கிற bytes.

By the end, you can

  • Keyboard-உம் screen-reader-உம் சேர்த்து ஒரு sanity check run பண்ண முடியும்.
  • பொதுவா வரும் WCAG failures-ஐ find பண்ணி fix பண்ண முடியும்.
  • தவிர்க்கக்கூடிய layout shift-ஐயும் download weight-ஐயும் குறைக்க முடியும்.

You need

  • இந்த course-ல நீங்கள் build பண்ணின ஒரு page.
  • Chrome DevTools-உம் Lighthouse-உம்.
  • Keyboard மட்டும் use பண்ணி பத்து நிமிடம்.

Access is a baseline

WCAG-ஓட full form Web Content Accessibility Guidelines. Perfect-ஆ இருக்கணும்-னு இல்ல, AA level-ஐ target பண்ணுங்கள். நான்கு principles-ஐ POUR-ஆ நினைவில் வைச்சா easy: content perceivable, operable, understandable, robust-ஆ இருக்கணும். Everyday code-ல இது ஆறு habits-ஆ வரும்.

  • Keyboard முதல். ஒவ்வொரு link, button, field, menu-உம் Tab, Shift+Tab, Enter, Space, எதிர்பார்க்கிற இடத்துல arrow keys-ஓட வேலை செய்யணும்.
  • Focus தெளிவா தெரியணும். Focus outline-ஐ replace பண்ணாம எப்பவும் remove பண்ணாதீர்கள். தெளிவான ring, keyboard users எங்க இருக்காங்க-னு காட்டும்.
  • Contrast. Body text-க்கு background-க்கு எதிரா குறைந்தது 4.5:1 வேணும். Large text-க்கும் interface boundaries-க்கும் குறைந்தது 3:1 வேணும்.
  • Names. ஒவ்வொரு input-க்கும் உண்மையான label இருக்கணும். அர்த்தம் உள்ள ஒவ்வொரு image-க்கும் useful alt text இருக்கணும். Decorative images alt="" use பண்ணும்.
  • Structure. ஒரு main, logical heading order, header, nav, footer போன்ற landmarks use பண்ணுங்கள். ஒரு skip link add பண்ணுங்கள்.
  • Motion. prefers-reduced-motion-ஐ respect பண்ணுங்கள்; எதையும் புரிஞ்சுக்க animation மட்டுமே வழியா இருக்கக் கூடாது.
Overlays are not a fix

Accessibility widget, button-ஆ நடிக்கிற div, label இல்லாத input, படிக்க முடியாத contrast — இதெல்லாம் fix பண்ண முடியாது. HTML-ஐயும் CSS-ஐயும் source-லயே fix பண்ணுங்கள்.

Run the same audit every time

இந்த checklist-ஐ print பண்ணுங்கள், இல்ல editor-க்கு பக்கத்துல வைத்திருங்கள். சின்ன site-ல முழு pass-க்கு சுமார் பதினைந்து நிமிடம் ஆகும்.

Fix the failures you can see

இந்த card ஒரு பொதுவான first draft. Click பண்ணலாம்-னு தெரியும், ஆனா keyboard-ல use பண்ண முடியாது, image-க்கு alternate இல்ல, low-contrast text பல readers-க்கு மறைஞ்சு போகும்.

Rewrite-ல உண்மையான article, உண்மையான link, useful alternative text, reserve பண்ணின image space, fold-க்கு கீழ இருக்கிற image-க்கு lazy loading, படிக்கக்கூடிய contrast use பண்ணியிருக்கு.

Focus-க்கும் motion-க்கும் CSS-உம் வேணும். Outline-ஐ strong-ஆ வைத்திருங்கள், visitor கேக்கும்போது motion-ஐ reduce பண்ணுங்கள்.

Test with a keyboard, not a checklist

Mouse-ஐ பக்கத்துல வைத்து main task-ஐ complete பண்ணுங்கள். Focus எங்க போச்சு-னு உங்களுக்குத் தெரியலைன்னா, keyboard user-க்கும் தெரியாது. அப்புறம் ஐந்து நிமிடம் screen reader try பண்ணுங்கள்; VoiceOver, NVDA, TalkBack free.

Performance is part of the experience

Slow devices-க்கும் unreliable networks-க்கும் performance என்பது accessibility. மிகப் பெரிய visible image, fonts, JavaScript-ல இருந்து start பண்ணுங்கள்.

  • Image space-ஐ reserve பண்ணுங்கள். width, height set பண்ணுங்கள், file வரும்போது layout jump ஆகாம இருக்க.
  • Fold-க்கு கீழ lazy-load பண்ணுங்கள். கீழ இருக்கிற images-க்கு loading="lazy" use பண்ணுங்கள். Hero image-ஐ lazy-load பண்ணாதீர்கள்; அது largest contentful paint-ஐ கெடுக்கும்.
  • Fonts swap ஆகணும். font-display: swap use பண்ணுங்கள், நீங்கள் use பண்ற weights மட்டும் load பண்ணுங்கள், ஒரே family-ஐ prefer பண்ணுங்கள்.
  • குறைவான JavaScript ship பண்ணுங்கள். Use பண்ணாத libraries-ஐ remove பண்ணுங்கள், scripts-ஐ defer பண்ணுங்கள், தேவைக்கு பெரிய files-க்கு Network panel-ஐ check பண்ணுங்கள்.
  • Mobile-ல measure பண்ணுங்கள். Mobile setting-உம் throttled connection-உம் போட்டு Lighthouse run பண்ணுங்கள். Desktop score என்பது உங்கள் visitors பெறுற score இல்ல.
Scores are a smoke alarm

Lighthouse score perfect-ஆ இருந்தா page accessible-னு prove ஆகாது. Automated tools problem-ஓட ஒரு part-ஐ மட்டும் பிடிக்கும்; keyboard testing-உம் human judgment-உம் மீதியை பிடிக்கும்.

Audit and repair a promo block

இந்த snippet-ல குறைந்தது ஐந்து accessibility problems-ஐ find பண்ணி, அப்புறம் rewrite பண்ணுங்கள். Heading உள்ள section, உண்மையான link அல்லது button, label உள்ள email field, useful alt text, image dimensions, படிக்கக்கூடிய contrast use பண்ணுங்கள். Image fold-க்கு கீழ இருக்கு-னு assume பண்ணுங்கள்.

Check yourself

Does a Lighthouse score of 100 mean the page is accessible?

இல்ல. Automated tests சில missing names, contrast failures, structural issues-ஐ பிடிக்கும், ஆனா keyboard order அர்த்தமா இருக்கா, screen-reader experience தெளிவா இருக்கா-னு judge பண்ண முடியாது. உண்மையான interaction-ஐ test பண்ணுங்கள்.

Why not add loading="lazy" to every image?

Lazy loading, browser தேவை-னு நினைக்கிற வரை image-ஐ delay பண்ணும். Hero-லயோ fold-க்கு மேல இருக்கிற மிகப் பெரிய image-லயோ அது page slow-ஆ feel ஆகும். Fold-க்கு கீழ இருக்கிற images-க்கு மட்டும் use பண்ணுங்கள்.

Key things to remember

  • Keyboard, focus, contrast, labels, alt, landmarks. ஒவ்வொரு page-லயும் அதே ஆறு checks-ஐ run பண்ணுங்கள்.
  • Performance என்பது user experience. Space-ஐ reserve பண்ணுங்கள், images-ஐ compress பண்ணுங்கள், ஒவ்வொரு kilobyte JavaScript-ஐயும் question பண்ணுங்கள்.
  • Scores மட்டும் இல்ல, மக்களோட audit பண்ணுங்கள். Automated tools conversation-ஐ start பண்ணும்; உண்மையான use அதை finish பண்ணும்.
