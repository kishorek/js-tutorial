fetch, JSON மற்றும் API keys

உங்கள் page மற்றொரு கணினியிடம் data கேட்கலாம். request/response cycle, fetch மற்றும் JSON எப்படி இணைகின்றன, secret keys ஏன் ஒருபோதும் browser code-ல் அனுப்பக்கூடாது என்பதைக் கற்றுக்கொள்ளுங்கள்.

பாடம் 6.2 60–75 நிமிடம் தொடக்கநிலை

இந்தப் பாடம் முடியும்போது, நீங்கள்:

  • ஒரு HTTP request மற்றும் response-ஐப் படியுங்கள்.
  • JSON-ஐ fetch செய்து response.ok-ஐச் சரிபாருங்கள்.
  • Query parameters கொண்டு request URLs உருவாக்குங்கள்.
  • CORS-ஐயும், secret keys-க்கு ஏன் server தேவை என்பதையும் விளக்குங்கள்.

  • DevTools திறந்த browser.

Request வெளியே போகும், response திரும்பி வரும்

API என்பது ஒரு ஒப்பந்தம்: நீங்கள் ஒரு URL-க்கு HTTP request அனுப்புகிறீர்கள், server ஒரு response அனுப்புகிறது. Request-க்கு ஒரு method இருக்கும்; எடுத்துக்காட்டாக data படிக்க GET, அனுப்ப POST. Response-க்கு status code, headers, மற்றும் பொதுவாக ஒரு body இருக்கும்.

நிலைபொருள்என்ன செய்ய வேண்டும்
200வெற்றிBody-ஐப் படியுங்கள்.
400தவறான requestURL அல்லது parameters-ஐச் சரிசெய்யுங்கள்.
401அனுமதி இல்லைServer-ல் சரியான credentials சேர்க்கவும்.
404கிடைக்கவில்லைPath அல்லது search term-ஐச் சரிபாருங்கள்.
429அதிகமான requestsவேகத்தைக் குறைக்கவும் அல்லது முடிவுகளை cache செய்யவும்.
500Server பிழைபின்னர் மீண்டும் முயலுங்கள்; இது உங்கள் URL-ன் பிரச்சினை அல்ல.

பெரும்பாலான நவீன APIs JSON-ஐ அனுப்புகின்றன: JavaScript objects மற்றும் arrays போலத் தெரியும் text. ஒரு weather response-ல் temperature மற்றும் weather code கொண்ட nested current object இருக்கலாம்.

fetch ஒரு promise-ஐத் திருப்பித் தரும்

fetch() ஒரு request-ஐத் தொடங்கி promise-ஐத் திருப்பித் தரும். 404 ஆனாலும், response headers வந்தவுடன் promise resolve ஆகும். அதனால்தான் body-ஐப் படிக்கும் முன் response.ok-ஐச் சரிபார்க்க வேண்டும்.

response.json()-ம் asynchronous. அது body-ஐப் படித்து JSON text-ஐ JavaScript values ஆக parse செய்கிறது, எனவே அதற்கும் await தேவை. Body சரியான JSON இல்லையென்றால், அது reject ஆகும்.

fetch, 404-ல் reject ஆகாது

Network failure promise-ஐ reject செய்யும். 404 அல்லது 500 போன்ற HTTP error இருந்தாலும் அது fulfill ஆகும். எப்போதும் response.ok-ஐச் சரிபாருங்கள்; இல்லையென்றால் error page-ஐ data ஆக parse செய்ய முயல்வீர்கள்.

Query parameters கொண்டு URL உருவாக்குங்கள்

Query parameters என்பவை ?-க்குப் பிறகு வரும் key=value இணைகள். அவை search-ஐ filter செய்யும், fields-ஐத் தேர்ந்தெடுக்கும், அல்லது options அமைக்கும். அவற்றை & கொண்டு பிரித்து, user input-ஐ encodeURIComponent() கொண்டு encode செய்யுங்கள்.

Open-Meteo-க்கு இரண்டு steps தேவை. முதலில் geocoding ஒரு city name-ஐ coordinates ஆக மாற்றும். பிறகு forecast endpoint அந்த coordinates-ஐப் பயன்படுத்தும். இரண்டும் இலவசம்; key தேவையில்லை.

CORS என்பது cross-origin requests-க்கான browser-ன் விதி. API சரியான Access-Control-Allow-Origin header-ஐ அனுப்பாவிட்டால், response-ஐப் படிக்கும் உங்கள் code-ஐ browser தடுக்கும். Client JavaScript-ல் இதைச் சரிசெய்ய முடியாது; API உங்கள் origin-ஐ அனுமதிக்க வேண்டும், இல்லையென்றால் server proxy தேவை.

CORS error-ஐப் படிப்பது

Network panel-ல் request response உடன் தெரியலாம்; ஆனால் console CORS failure-ஐக் காட்டும். Browser data-ஐப் பெற்றுக்கொண்டது, ஆனால் உங்கள் page-க்கு அதை வெளிப்படுத்த மறுத்துவிட்டது.

API keys server-ல் இருக்க வேண்டும்

சில APIs caller-ஐ அடையாளம் காணவும் bill செய்யவும் ஒரு key பயன்படுத்துகின்றன. Public key தெரிவதற்காகவே வடிவமைக்கப்பட்டு domain மூலம் கட்டுப்படுத்தப்படும். Secret key அப்படி அல்ல. HTML, CSS, அல்லது client JavaScript-ல் உள்ள எதையும் ஒவ்வொரு visitor-ம் படிக்கலாம்.

Key-ஐ ஒரு variable, comment, அல்லது obfuscate செய்யப்பட்ட file-ல் மறைப்பது security அல்ல. Browser key-ஐ request உடன் அனுப்ப வேண்டும், எனவே அது DevTools-ல் தெரியும். Client code-ல் உள்ள secret key-ஐ நகலெடுத்து உங்கள் account-க்கு எதிராகப் பயன்படுத்தலாம்.

Key தேவைப்பட்டால், அதைச் சிறிய server அல்லது serverless function-ல் வையுங்கள். Key server-ல் environment variable ஆக வாழும். உங்கள் browser உங்கள் endpoint-ஐ அழைக்கும்; உங்கள் endpoint API-ஐ அழைத்து page-க்குத் தேவையான data-வை மட்டும் திருப்பித் தரும்.

Key-ஐ ஒருபோதும் commit செய்யாதீர்கள்

Secrets-ஐ public repository, screenshot, அல்லது shared chat-ல் வைக்காதீர்கள். Secret key leak ஆனால், அதை revoke செய்து புதியதை உருவாக்குங்கள். Open-Meteo-க்கு key தேவையில்லை; அதனால் பயிற்சி செய்ய இது பாதுகாப்பான இடம்.

உங்களைச் சரிபாருங்கள்

404 response தானாக ஏன் error throw செய்யாது?

Request முழுமையாக முடியாதபோது மட்டுமே—உதாரணமாக network failure—fetch promise reject ஆகும். HTTP 404 என்பது முடிந்த response, எனவே promise fulfill ஆகும். response.ok-ஐச் சரிபார்த்து, அது false ஆகும்போது உங்கள் சொந்த error-ஐ throw செய்யுங்கள்.

JavaScript variable-ல் key மறைக்கப்பட்டால் அது பாதுகாப்பானதா?

இல்லை. Browser key-ஐ API-க்கு அனுப்ப வேண்டும், எனவே அது DevTools, source files, அல்லது Network panel-ல் தெரியும். Secret keys server-ல், environment variables-ல் இருந்து படிக்கப்பட்டு, உங்கள் page அழைக்கக்கூடிய endpoint-க்குப் பின்னால் இருக்க வேண்டும்.

நினைவில் கொள்ள வேண்டிய முக்கிய விஷயங்கள்

  • fetch asynchronous. Response-க்காக await செய்து, response.ok-ஐச் சரிபார்த்து, பிறகு response.json()-க்காக await செய்யுங்கள்.
  • URLs தான் request-ஐ எடுத்துச் செல்கின்றன. User input-ஐ encode செய்து, search terms மற்றும் options-க்கு query parameters பயன்படுத்துங்கள்.
  • CORS மற்றும் keys server-ன் பொறுப்பு. தடுக்கப்பட்ட response-க்கு உங்கள் origin-ஐ அனுமதிக்கும் API அல்லது proxy தேவை; secrets ஒருபோதும் browser-ல் இருக்கக்கூடாது.
