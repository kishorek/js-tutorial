Module 05 · DOM & events

State and rendering lists

ஒவ்வொரு click-ம் page-ஐ நேரடியா edit பண்ணும்போது lists குழப்பமாகும். Truth-ஐ ஒரு சின்ன state array-ல வையுங்கள், ஒரு render function write பண்ணுங்கள், எல்லா actions-ஐயும் அதே path-ல போக விடுங்கள்.

State first, then render

State என்ன data-ஐ screen depend பண்ணுதோ அது. ஒரு list-க்கு அது objects-ஓட array. கண்ணுக்குத் தெரியும் list items-ஐ source of truth-ஆ நினைக்காதீங்க; அவை array-ஓட ஒரு rendering மட்டும் தான்.

ஒவ்வொரு change-ம் அதே மூணு steps-ஐ follow பண்ணும்: state-ஐ update பண்ணுங்கள், render-ஐ call பண்ணுங்கள், screen தானா match ஆகட்டும். Render function எது true-ன்னு முடிவு பண்ணாது; current array-ஐ மட்டும் describe பண்ணும்.

Why start over

சின்ன list-ஐ clear பண்ணி மறுபடி build பண்றது fast-ம் predictable-ம். ஒரு row update ஆகி இன்னொன்னு stale ஆகிற bugs முழுசா போயிடும். ரொம்ப பெரிய lists-க்கு பிறகு தனி nodes-ஐ update பண்ணுங்கள்.

Add, toggle, and remove

ஒரு id, DOM-ல இருக்கும் button-ஐ state-ல இருக்கும் ஒரு object-ஓட connect பண்ணும். அதை data-id attribute-ல வச்சு dataset.id மூலம் read பண்ணுங்கள். Attribute values strings-ஆ தான் வரும். Render ஆகும் ஒவ்வொரு row-க்கும் data-action toggle அல்லது remove ஆக இருக்கும் button வேணும்; exercise-ல முழு row-ஐயும் build பண்ணுவோம்.

list-ல இருக்கும் ஒரு listener ஒவ்வொரு render-க்கு அப்புறமும் வேலை செய்யும், ஏன்னா அது buttons-ல இல்லாம parent-ல listen பண்ணுது. filter removed item இல்லாத புது array-ஐ create பண்ணும்; map ஒரு object change ஆன புது array-ஐ create பண்ணும். ரெண்டும் அடுத்த render-க்கு feed ஆகும்.

User text DOM-க்கு textContent மூலமா தான் போகணும், HTML string மூலமா கூடாது. ஒரு item-ஓட text-ல <b> இருந்தா, visitor-க்கு characters தான் தெரியணும், bold text இல்ல.

Empty states and filters

Filter-ம் state தான். Current choice-ஐ ஒரு variable-ல store பண்ணி, visible subset-ஐ build பண்ணி, அதை render பண்ணுங்கள். Empty result-க்கு காலி box-க்கு பதிலா ஒரு message இருக்கணும்.

Filter button change ஆகும்போது variable-ஐ set பண்ணி render function-ஐ மறுபடி call பண்ணுங்கள். Empty message-ஐ அதே list-ல வையுங்கள், அப்போ தான் layout தனி element-க்கு jump ஆகாது.

Render, add, and toggle a list

Page-ல <ul id="list">, <form id="add-form">, <input id="new-item"> இருக்குன்னு வச்சுக்கோங்க. ரெண்டு objects-ஓட array-ல தொடங்குங்கள். ஒவ்வொரு item-ஐயும் text span-ம் toggle button-ம் மூலமா render பண்ணுங்கள், array காலியா இருந்தா empty message show பண்ணுங்கள், submit-ல trimmed item-ஐ add பண்ணுங்கள், ஒரு delegated click listener மூலமா done-ஐ toggle பண்ணுங்கள்.

Make an attempt first. Then the model answer unlocks.

Check yourself

Why rebuild the whole list instead of changing one row?

Full render எப்பவுமே state array-க்கு match ஆகும்; அதனால filters, counts, empty messages sync-ஐ விட்டு விலக முடியாது. சின்ன lists-க்கு maintain பண்றதும் குறைவான code.

Why use an id instead of the item's position?

Item remove ஆனப்போ அல்லது filter ஆனப்போ positions change ஆகும். Array மறுபடி build ஆனப்புறமும் ஒரு stable id சரியான object-ஐ சுட்டும்.

Key things to remember

  • State தான் source of truth. DOM array-ஐப் பார்க்கிற projection தான்; array அது இல்ல.
  • State-ஐ change பண்ணி, பிறகு render பண்ணுங்கள். Add, toggle, remove, filter எல்லாத்துக்கும் ஒரே path இருந்தா behavior predictable-ஆ இருக்கும்.
  • Ids-ஐயும் textContent-ஐயும் use பண்ணுங்கள். Data attributes controls-ஐ items-ஓட connect பண்ணும்; plain text user input-ஐ safe-ஆ வைக்கும்.
