Selectors, cascade, and specificity

CSS என்பது rule-களின் list. Selector elements-ஐ select பண்ணும், declaration என்ன மாறுதல் என்று சொல்லும், இரண்டு rule-கள் முரண்படும்போது எது win பண்ணும் என்று cascade decide பண்ணும். இந்த order-ஐ ஒருமுறை understand பண்ணிட்டா, CSS random-ஆ தெரியுறது நிற்கும்.

Connect a stylesheet

CSS தனி file-ல இருக்கும், அதை <head>-ல இருந்து link பண்ணுவோம். href என்பது நீங்கள் ஏற்கனவே எழுதுன links-ஐப் போலவே ஒரு relative path. ஒரு rule-ல braces-க்கு முன்னாடி selector, உள்ளே declarations இருக்கும். ஒவ்வொரு declaration-ம் property, ஒரு colon, ஒரு value, ஒரு semicolon.

ஒரு idea-க்கு ஒரு rule எழுதுங்கள்; file-ஐ நல்ல order-ல வையுங்கள்: reset, base elements, layout, components, utilities. Browser rules-ஐ top-ல இருந்து bottom வரை read பண்ணும்.

Selectors choose elements

வேலை செய்யுற least powerful selector-ல இருந்து start பண்ணுங்கள். Classes reusable, அதனால components-க்கு அவைதான் சரியான default. Ids page-ல ஒரே ஒரு element-க்கு மட்டும்; anchors, JavaScript hooks-க்கு வைச்சுக்கோங்க.

  • Element: match ஆகுற ஒவ்வொரு tag-க்கும், எல்லா இடத்திலும் apply ஆகும். Base styles-க்கு use ஆகும்.
  • Class: .card என்று எழுதி class="card"-உடன் match ஆகும். Reusable, பெரும்பாலான வேலைக்கு போதுமான specificity உள்ளது.
  • Id: #intro என்று எழுதி id="intro"-உடன் match ஆகும். Page-க்கு ஒண்ணு; அப்புறம் override பண்ண கஷ்டம்.
  • Descendant: .card p என்றால் card-க்கு உள்ளே எந்த depth-ல இருந்தாலும் எந்த paragraph-ஐயும் குறிக்கும்.
  • Pseudo-class: :hover, :focus-visible, :first-child போன்ற ஒரு state.

Selectors-ஐ shallow-ஆ வையுங்கள். main .card div h3-ஐ விட .card__title read பண்ணவும் override பண்ணவும் easy; markup மாறினாலும் அது survive ஆகும்.

The cascade breaks ties by order

ஒரே element-ல ஒரே property-ஐ இரண்டு rules set பண்ணினா, selectors-க்கு equal weight இருந்தா later rule win பண்ணும். கீழே scroll பண்ணுவதுக்கு முன்னாடி color-ஐ predict பண்ணுங்கள்.

Paragraph green-ஆ இருக்கும். இரண்டு selectors-க்கும் same specificity, அதனால source order decide பண்ணும்: second declaration first-ஐ replace பண்ணும். அதனாலதான் stylesheet-ஓட order important.

Specificity has weights

Specificity என்பது four-part score. Left-ல இருந்து right-க்கு compare பண்ணுங்கள்; ஒரு id எத்தனை classes-ஐயும் beat பண்ணும். Inline styles தனி, stronger category; !important normal declarations-க்கு மேலே இருக்கும்.

Class, attribute, pseudo-class0-0-1-0.note, a:hover
Element, pseudo-element0-0-0-1p, p::first-line
Universal0-0-0-0*

இப்போ இரண்டு paragraphs-ஐயும் predict பண்ணுங்கள். முதல் paragraph-க்கு id இருக்கு; இரண்டாவது selector-ல class-ம் element-ம் இருக்கு.

முதல் paragraph red: #intro score 0-1-0-0, எல்லா class rules-ஐயும் outrank பண்ணும். இரண்டாவது gray: p.note score 0-0-1-1, அது 0-0-1-0 உள்ள .note-ஐ beat பண்ணும். Classes-ஐ count பண்ணுங்கள், அப்புறம் elements-ஐ; columns-ஐ add பண்ணாதீங்க.

A card, styled

சிறிய, predictable component-ல box-க்கு ஒரு class, ஒவ்வொரு part-க்கும் ஒரு class: .card, .card__title, .card__text. ஒவ்வொரு selector-ம் 0-0-1-0 score, அதனால last matching rule win பண்ணும்; id-உடன் எந்த fight-ம் இல்லை.

Inheritance and the last resort

color, font-family, line-height போன்ற சில properties parent element-ல இருந்து inherit ஆகும். margin, padding, border போன்றவை ஆகாது. Inherited properties-ஐ body-ல ஒருமுறை set பண்ணுங்கள், page முழுவதும் follow ஆகும்.

Avoid !important

!important normal cascade-ஐ override பண்ணும். உங்களோடதை beat பண்ண அடுத்தவர் இன்னொரு !important add பண்ணணும்; file ஒரு fight ஆயிடும். Third-party CSS-ஐ வேண்டும்னே, document பண்ணி override பண்ணும்போது மட்டும் use பண்ணுங்கள். உங்கள் styles-க்கு selector-ஐ அல்லது order-ஐ fix பண்ணுங்கள்.

Check yourself

Why does one id beat several classes?

Specificity categories-ஐ total count-ல அல்ல, left-ல இருந்து right-க்கு compare பண்ணும். Id second column-க்கு contribute பண்ணும்; classes third column-க்கு. எத்தனை class names stack பண்ணினாலும் 0-1-0-0 score 0-0-9-0-ஐ beat பண்ணும்.

Is !important ever the right choice?

அரிதா. உங்கள் control-ல இல்லாத, selector-ஐ மாற்ற முடியாத CSS-ஐ override பண்ண வேண்டியிருக்கும்போது (vendor widget போல) இது justify பண்ணலாம். உங்கள் code-க்கு specificity-ஐ வேண்டும்னே increase பண்ணுங்கள் அல்லது rule-ஐ later-க்கு move பண்ணுங்கள். எந்த exception-ஐயும் document பண்ணுங்கள்.

Key things to remember

  • Classes-தான் default tool. Reusable, readable, override பண்ண easy.
  • Specificity-ஐ column column-ஆ compare பண்ணணும். Inline id-ஐ beat பண்ணும், id class-ஐ beat பண்ணும், class element-ஐ beat பண்ணும்.
  • Tie-ஐ order decide பண்ணும். Weight equal-ஆ இருந்தா later declaration win பண்ணும்; stylesheet-ஐ organised-ஆ வையுங்கள்.
