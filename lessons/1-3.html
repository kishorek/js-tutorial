Module 01 · HTML: the skeleton

Tables, forms, and semantic structure

Tables are for data, forms are for input, and landmarks give a page a shape that assistive technology can navigate. This is where HTML starts to feel like a language instead of a list of tags.

Lesson 1.3 60–75 min Beginner

By the end, you can

  • Build a table with a caption and header cells.
  • Create a form with labels, grouped fields, and a submit button.
  • Choose semantic landmarks for a page layout.

You need

  • Lesson 1.2 completed.
  • A browser with DevTools.
  • A page that already has a heading outline.

Tables are for tabular data

Use a table when information has rows and columns that relate to each other. Do not use one to position a page layout; CSS Grid does that job better.

  • <caption> names the table. Put it immediately after the opening tag.
  • <thead> and <tbody> group header and body rows.
  • <th scope="col"> labels a column; scope="row" labels a row.
  • Keep one idea per cell and make numbers easy to scan.

Forms collect input

A form needs a label for every field, a sensible input type, and a button. Labels are not decoration: clicking the label should focus its field, and screen readers use it as the field's name.

  • Match every for to an input's id.
  • Use type="email", type="number", or type="date" when it fits; mobile keyboards adapt.
  • required makes the field mandatory before submission.
  • fieldset and legend group related controls.
  • A form without a backend still validates in the browser. We will wire JavaScript to it later.
Do not use a placeholder as a label

Placeholders disappear as soon as someone types, and they are not a reliable accessible name. Keep a real label and use placeholder text only for an example.

Give the page landmarks

Semantic elements tell the browser what each region does. A visitor can see the header; a screen reader can jump straight to main or nav.

Only one main per page. Use section for a themed group of content and article for something that could stand on its own, like a blog post or a project card.

Exercise · 25 minutes

Build an accessible signup page

Create a page with a header, main, and footer. Inside main, add a table of three study sessions and a form with a name field, an email field, a goals textarea, and a submit button. Every input needs a label. The table needs a caption and column headers.

Make an attempt first. Then the model answer unlocks.

Check yourself

Why should a table have a caption?

The caption gives the table a name and context before a screen reader starts reading rows and columns. It also helps sighted users understand what they are looking at.

What is the difference between section and article?

A section groups related content under a heading. An article is self-contained content that could be reused elsewhere, such as a post or a project card.

Key things to remember

  • Tables are for data, not layout. Caption it and label headers.
  • Every form field needs a label. Match for and id.
  • Landmarks make a page navigable. Header, nav, main, aside, footer.
