Storage + weather app

Build the module project: a small weather app that searches a city, shows current conditions, survives a refresh, and never leaves the user staring at a blank screen.

Lesson 6.4 · Project2–3 hoursModule milestone

Deliverables

  • City search with Open-Meteo geocoding.
  • Current temperature and weather description.
  • Loading, empty, error, and success states.
  • Last city saved in localStorage.

Exit check

  • No unhandled errors in the console.
  • Every state is reachable and visible.
  • Reload restores the last successful city.
  • No secret keys anywhere in the page.

The brief

Build one page with a search form, a status line, and a result area. Use the free Open-Meteo APIs: geocoding turns a city name into coordinates, then the forecast endpoint returns the current temperature and weather code. No key is required.

Requirements

  • A labelled city input and a submit button that work with the keyboard.
  • Geocode with count=1; handle an empty results array.
  • Fetch temperature_2m and weather_code for the first match.
  • Render loading, empty, error, and success from one state function.
  • Save the successful city and restore it on the next visit.
  • Use aria-live="polite" for status and textContent for API text.

State checklist

  • Idle: a short instruction before the first search.
  • Loading: a message while either request runs; hide stale results.
  • Empty: geocoding returned no match; suggest another spelling.
  • Error: network or HTTP failure; explain and offer the form as retry.
  • Success: place, rounded temperature, and a readable description.
  • Storage: save only after success; blocked storage must not break the app.

Save a city and a unit

localStorage keeps data after the tab closes. sessionStorage keeps it only for the current tab. Both store strings, so convert objects with JSON.stringify() and read them back with JSON.parse().

Wrap storage calls in try/catch. A browser can block storage in private modes or sandboxed previews, and setItem() throws when the quota is full. In the editor preview, storage may be blocked, so the warning path is part of the exercise.

Privacy and limits

Storage belongs to your origin and is readable by any script on that page. Do not store tokens, passwords, or personal data. Expect only a few megabytes, and provide a way to clear saved settings.

Check yourself

Why save the city instead of the temperature?

Weather changes constantly. A saved city is a stable preference; a saved temperature would be stale as soon as the page reloads. Store the choice, then fetch fresh data.

Why wrap localStorage calls in try/catch?

Storage can be blocked in private modes and sandboxed previews, and setItem() can fail when the quota is full. Catching the error keeps the weather app usable even when saving is not.

Module 6 complete

  • Async code is a sequence of states. Promises and async/await let you write that sequence clearly.
  • Every request can fail or find nothing. Design loading, empty, error, and success before you need them.
  • Store only what you can afford to lose. Wrap storage, keep secrets on the server, and restore the last useful choice.
