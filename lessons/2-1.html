Module 02 · CSS: the skin

Selectors, cascade, and specificity

CSS is a list of rules. A selector chooses elements, declarations describe the change, and the cascade decides which rule wins when two rules disagree. Learn that order once and CSS stops feeling random.

By the end, you can

  • Use element, class, id, descendant, and pseudo-class selectors.
  • Predict which declaration wins and explain why.

Connect a stylesheet

CSS lives in its own file and is linked from the <head>. The href is a relative path, just like the links you already wrote. A rule has a selector before the braces and declarations inside. Each declaration is a property, a colon, a value, and a semicolon.

Write one rule per idea and keep the file in a sensible order: reset, base elements, layout, components, utilities. The browser reads rules from top to bottom.

Selectors choose elements

Start with the least powerful selector that does the job. Classes are reusable, so they are the right default for components. Ids are unique to one element on the page; save them for anchors and JavaScript hooks.

  • Element: every matching tag, everywhere. Useful for base styles.
  • Class: written .card and matched with class="card". Reusable and specific enough for most work.
  • Id: written #intro and matched with id="intro". One per page; hard to override later.
  • Descendant: .card p means any paragraph inside a card, at any depth.
  • Pseudo-class: a state such as :hover, :focus-visible, or :first-child.

Keep selectors shallow. .card__title is easier to read and override than main .card div h3, and it survives markup changes.

The cascade breaks ties by order

When two rules set the same property on the same element, the later rule wins if the selectors have equal weight. Predict the color below before you scroll on.

Specificity has weights

Specificity is a four-part score. Compare it from left to right; a single id beats any number of classes. Inline styles are a separate, stronger category, and !important sits above normal declarations.

The first paragraph is red: #intro scores 0-1-0-0 and outranks every class rule. The second is gray: p.note scores 0-0-1-1, which beats .note at 0-0-1-0. Count the classes, then the elements; do not add the columns together.

A card, styled

A small, predictable component uses a class for the box and a class for each part: .card, .card__title, .card__text. Each selector scores 0-0-1-0, so the last matching rule wins and nothing is fighting an id.

Inheritance and the last resort

Some properties, such as color, font-family, and line-height, inherit from the parent element. Others, such as margin, padding, and border, do not. Set inherited properties once on body and let the page follow.

Avoid !important

!important overrides the normal cascade. The next person has to add another !important to beat yours, and the file becomes a fight. Use it only for a deliberate, documented override of third-party CSS. For your own styles, fix the selector or the order instead.

Check yourself

Why does one id beat several classes?

Specificity compares categories from left to right, not by total count. An id contributes to the second column; classes contribute to the third. A score of 0-1-0-0 beats 0-0-9-0 no matter how many class names are stacked up.

Is !important ever the right choice?

Rarely. It is defensible when you must override CSS you do not control and cannot change the selector, such as a vendor widget. For your own code, increase specificity intentionally or move the rule later. Document any exception.

Key things to remember

  • Classes are the default tool. They are reusable, readable, and easy to override.
  • Specificity is compared column by column. Inline beats id, id beats class, class beats element.
  • Order decides ties. If the weight is equal, the later declaration wins; keep your stylesheet organized.
