Module 05 · DOM & events

Events, input, and forms

A page becomes interactive when it listens. Learn how events travel, how to read what a visitor typed, and how to handle a form without losing their work to a page reload.

An event is a message

When something happens, the browser creates an event object and sends it to the element. You listen with addEventListener(type, handler).

The handler receives the event. event.target is the element that fired it; event.currentTarget is the element the listener is attached to. They are the same on a simple button, but different when a parent listens for its children.

Use addEventListener instead of an onclick attribute. It keeps behaviour in JavaScript, allows more than one listener, and is easier to remove later with removeEventListener.

Read the value as it changes

The input event fires every time the value changes. Read input.value for text, input.checked for a checkbox, and select.value for a drop-down.

input fires on every keystroke or paste. change waits until the field loses focus or the choice is committed. For a live counter or preview, choose input.

Values are strings

input.value is always a string, even for a number field. Convert with Number(input.value) before doing maths, and check for an empty string first.

Submit a form without reloading

A form submits by default: the browser sends the data and loads a new page. To handle it in JavaScript, listen for submit and call event.preventDefault().

FormData reads fields by their name attributes, not their ids. Every field still needs a label connected to an id for people using assistive technology. Built-in rules such as required and type="email" run before submit; server-side validation is still necessary.

Keyboard events and delegation

Keyboard users need the same actions as mouse users. Listen for keydown and compare event.key with a name such as "Enter" or "Escape". Do not compare numeric keyCode values.

The second listener is event delegation. One listener on the parent handles every matching child, including children added later. closest walks up from the clicked element to find the button, so clicking the button's text still works.

Check yourself

What is the difference between input and change?

input fires on every edit, including each keystroke. change fires when the edit is committed, usually on blur or when a select value is chosen.

Why does the page reload when I submit a form?

That is the browser's default behaviour. Your submit handler runs first; event.preventDefault() stops the navigation so your code can update the page instead.

Key things to remember

  • Listen, then read. Attach a listener and use the event object to learn what happened.
  • Prevent the default only when you handle it. A submit handler that forgets preventDefault loses the page.
  • One parent can handle many children. Delegation with closest survives new rows.
