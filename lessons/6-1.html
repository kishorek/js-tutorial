Promises and async/await

JavaScript does not wait for slow work. Learn how promises represent work that finishes later, and how async and await make that flow read like ordinary code.

JavaScript does not wait

Synchronous code runs one line at a time, in order. Each line finishes before the next one starts. That is easy to reason about, but a slow operation would freeze everything behind it.

Asynchronous code starts a task, moves on, and handles the result later. Timers, network requests, and file reads are asynchronous. The callback runs after the current work finishes, even if the delay is zero milliseconds.

For years, callbacks were the main way to handle this. They work, but nesting several of them creates a pyramid that is hard to read and harder to debug. Promises were introduced to flatten that shape.

One mental model

A promise is a receipt for a value that is not ready yet. You can attach handlers now, and they run when the value arrives.

Promises have three states

A promise is pending while the work runs. It becomes fulfilled with a value, or rejected with an error. Once settled, it cannot change again.

Create one with the Promise constructor. Call resolve with the result, or reject with an Error.

Use .then() to handle a fulfilled value, .catch() to handle a rejection, and .finally() for cleanup that should run either way.

Each .then() returns a new promise. Returning a promise from a handler makes the next .then() wait for it. That is what keeps the chain flat instead of nested.

Do not forget to return

If a .then() handler starts a promise but does not return it, the next step runs too early. The chain looks correct and quietly produces the wrong order.

async and await

An async function always returns a promise. Inside it, await pauses that function until the promise settles, without blocking the rest of the page. The code reads from top to bottom again.

This is the same logic as the chain above. The try block handles success, catch handles a rejected promise, and finally runs afterward. await only works inside an async function or at the top level of a module.

Do not mix the styles without a reason. Pick async/await for most code, and use .then() when you are already working with a promise chain or need a small inline handler.

Wait together, not one by one

Two independent requests do not need to run in sequence. Promise.all() starts them together and resolves when every promise fulfills. If any one rejects, the combined promise rejects.

Use Promise.all() when every result is required. If one failure should not cancel the others, use Promise.allSettled() instead and inspect each result.

Check yourself

What is the difference between pending and fulfilled?

Pending means the work is still running and the promise has no final value yet. Fulfilled means it finished successfully and now holds a value. A promise can only settle once.

Why does await not freeze the rest of the page?

await pauses only the async function that contains it. The browser's main thread is released, so other events, rendering, and user input can continue while the promise is pending.

Key things to remember

  • Async work finishes later. A promise is a placeholder for a value that may arrive or fail.
  • Return promises from .then(). That keeps a chain in order; forgetting the return makes later steps run too early.
  • async/await is the readable default. Use try/catch for failure and Promise.all for independent work.
