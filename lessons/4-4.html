Functions and scope

Functions turn a block of steps into a named tool you can reuse, test, and pass around. Learn parameters, return values, arrow syntax, scope, and the difference between a pure function and one that fights the rest of your code.

Functions name reusable work

A function declaration starts with the function keyword, a name, a parameter list, and a body. Declaring it does not run it. You run it by calling the name with parentheses.

The word name inside the parentheses is a parameter, a placeholder for a value. The value you pass when calling, such as "Maya", is an argument. Inside the function, the parameter behaves like a normal variable.

Parameters and return values

return sends a value back to the caller and stops the function immediately. Without a return statement, a function returns undefined.

Logging and returning are different jobs. A function that logs is useful for a human watching the console. A function that returns is useful to the rest of the program, because another function can use the result.

Code after return never runs. If you need to compute something before returning, do the work first.

Expressions and arrow functions

A function expression stores a function in a variable. The function may be anonymous, which is common when passing it to another method.

An arrow function is a shorter expression syntax. With one parameter, the parentheses are optional. With a single expression, the braces and return are optional too.

Arrow functions are excellent for short callbacks. They differ from ordinary functions in how they handle this, but you will not need that distinction until you work with objects and events in Module 5.

Defaults and scope

A default parameter supplies a value when the caller omits an argument. Defaults are evaluated when the function runs, not when it is declared.

Scope is the set of names a piece of code can see. A variable declared inside a function is local: it exists only during that call. A variable declared outside is global to the file and visible inside functions.

Block scope also applies to let and const inside loops and if blocks. Prefer local variables: they are easier to reason about and cannot be changed by unrelated code.

Avoid accidental globals

Assigning to a name that was never declared creates a global in non-strict code. Always declare with const or let so a typo becomes an error instead of a hidden variable.

Pure functions and callbacks

A pure function returns the same output for the same input and changes nothing outside itself. Pure functions are easy to test because you can call them repeatedly without side effects.

Impure functions are not forbidden. They are necessary for saving data, updating a page, or logging. The habit to build is to keep calculation pure and push side effects to the edges of the program.

A callback is a function passed to another function so it can be called later. The array methods from Lesson 4.3 use callbacks. You can write your own too.

Passing a function as a value is what makes callbacks possible. Notice that action is called with parentheses; passing action() instead would call it immediately and pass its result.

Check yourself

What happens if a function has no return statement?

It returns undefined. The function still runs, so logging inside it still prints, but the caller receives no useful value. If you need the result elsewhere, return it.

Why can a function see taxRate but not a variable declared inside another function?

Scope looks outward, not sideways. A function can read names from the surrounding file, but a local variable belongs only to the call that created it. Each function's inner names stay private.

Key things to remember

  • Functions are named steps with inputs and an output. Parameters receive arguments; return sends a result back.
  • Scope keeps names local. Declare with const or let and prefer variables that live only where they are needed.
  • Pure functions are predictable. Keep calculations pure, use callbacks for reusable behavior, and let side effects happen at the edges.
