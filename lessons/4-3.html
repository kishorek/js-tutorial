Loops and collections

Real programs work with more than one value. Learn to store lists in arrays, visit every item with a loop, and transform data with map, filter, and reduce instead of writing the same loop again and again.

Arrays hold ordered lists

An array stores several values in order. Square brackets create one, and each item has an index. Indexes start at zero, so the first item is at 0, not 1.

  • push(item) adds to the end and returns the new length.
  • pop() removes the last item and returns it.
  • shift() and unshift() work at the start, but are slower on large arrays.
  • Reading past the end gives undefined; it does not throw an error.

Arrays can hold any type, including other arrays. For beginners, keeping one kind of value per array makes the code easier to reason about.

for loops repeat work

A for loop has three parts: a starting point, a condition that keeps it running, and an update after each pass. The middle part is checked before every iteration.

When looping over an array with indexes, start at 0 and stop while the index is less than array.length. Using <= reads one item past the end and gives undefined.

A while loop repeats as long as a condition is true. Use it when you do not know the number of passes in advance, but make sure something changes inside the loop.

Avoid the infinite loop

If the condition never becomes false, the page freezes. Check that the loop body updates the value used in the condition. In a browser, you may need to close the tab.

for...of reads values directly

When you only need each value, for...of is shorter and harder to get wrong than an index loop. It visits the values in order.

Use the classic for loop when you need the index as well as the value, or when you need to skip items. Use for...of when you just want each item.

Transform with map, filter, and reduce

Many loops follow the same three patterns: change every item, keep some items, or boil the list down to one value. JavaScript provides a method for each.

MethodJobReturns
mapTransform every itemA new array of the same length
filterKeep items that pass a testA new, usually shorter array
reduceCombine all items into one valueA single value

The callback you pass to map runs once per item and returns the replacement. The callback for filter returns true to keep an item and false to drop it. The callback for reduce receives the running result and the current item; the second argument to reduce is the starting value.

Keep the original

map, filter, and reduce do not change the original array. They return a new value. That makes them safe to chain and easy to test.

Check yourself

Why does array[array.length] return undefined?

Indexes run from 0 to length - 1. Asking for the index equal to the length points one position past the last item. Use array[array.length - 1] for the final item.

When should I use reduce instead of a loop?

Use reduce when the result is a single value built from every item, such as a sum, a count, or a lookup object. For side effects or early exit, a plain loop is often clearer.

Key things to remember

  • Arrays start at zero. length is one more than the last index.
  • Choose the loop for the job. Index loop for positions, for...of for values, while for unknown counts.
  • map, filter, and reduce replace repeated loop patterns. They return new values and leave the original array alone.
