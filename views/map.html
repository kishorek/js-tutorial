The route

Every module has a job, a project, and an exit check. You do not move on because the calendar says so. You move when the exit check is true.

The section menu on the left lists every lesson. Your progress is saved in this browser.

Every lesson is a loop

Understanding beats memorizing. Each lesson introduces one idea, shows it in code, has you predict the result, then asks you to build something small with it.

  1. Predict before you run. A wrong prediction shows exactly where your mental model breaks.
  2. Type, don't paste. Typing forces you to notice brackets, quotes, and closing tags.
  3. Break it on purpose. Remove a tag, change a name, see the result, then repair it.
  4. Explain it simply. If you cannot explain it in one minute, you do not own it yet.

How you're assessed

  • Every lesson: a quick check and one micro-build. You produce code, not just recognize it.
  • Every module: a project reviewed against a checklist and a short quiz. The exit check is the gate.
  • Every project: you demo it, then change one thing live. If you can adapt it, you understand it.
When something doesn't click

Struggle is data, not failure. If a lesson scores below the exit check, reread it, rebuild the exercise from a blank file, then try a fresh variant. The section menu and progress tracker make it easy to return.

Before you start

  • A browser. Chrome, Firefox, Safari, or Edge. You will use DevTools constantly.
  • A text editor. VS Code is the usual choice, but any plain-text editor works.
  • A course folder. Call it web-builder. Keep every exercise inside it.
  • Curiosity, not confidence. You are allowed to not know yet.
